## 2. 画面概要・目的

### 2.1 目的
レビュー・コンテンツ管理画面は、プラットフォームの整合性を維持するための中央管理ハブとして機能します。管理者が製品レビューのモデレーション（承認/却下/削除）、出品者登録の管理（承認/却下）、製品コンテンツのモデレーション（有効化/無効化）、ユーザーアカウントのモデレーション（有効化/無効化）を実行できるようにします。すべてのアクションは管理者専用のRBACによって保護されています。

### 2.2 対象ユーザーと権限

| 属性 | 値 |
| :--- | :--- |
| **主アクター** | プラットフォーム管理者（管理者） |
| **必要認証** | `admin`ロールを持つJWT Bearer Token |
| **データ範囲** | すべてのレビュー、製品、出品者、ユーザーアカウント |
| **アクセス制御** | 保護されたルート — `JwtAuthGuard` + `RolesGuard`（`admin`） |

### 2.3 主要機能・基本設計方針
1. **レビューモデレーション** — 監査ログ付きで製品レビューの表示、承認、却下、削除。
2. **コンテンツモデレーション** — すべての製品の表示、違反コンテンツの無効化（`is_active = false`）、製品の有効化、プラットフォームポリシーの適用（UC-MOD-004, BR-MOD-010~013）。
3. **出品者登録管理** — 出品者ショップ登録の承認または却下。
4. **ユーザーアカウントモデレーション** — すべてのユーザーの表示、ポリシー違反によるユーザーアカウントの有効化/無効化（UC-MOD-006, BR-MOD-040~042）。管理者は自分自身を無効化できません。
5. **リアルタイムフィードバック** — すべてのモデレーションアクションに対するトースト通知。
6. **確認ダイアログ** — すべての破壊的アクション（削除、却下、無効化）に必須。
7. **ページネーションとフィルタリング** — サーバーサイドページネーション付きタブベースステータスフィルタ。
8. **国際化** — EN、JA、MYの完全なi18nサポート。

## 5. 各項目における挙動・イベント仕様

### 5.1 レビュータブフィルタ変更（`tabFilterReviews` onChange）
- **トリガー:** ユーザーがフィルタタブ（すべて、承認済み、却下済み）をクリック。
- **処理ロジック:**
  1. URLクエリパラメータ `?status=approved|rejected` を更新、または「すべて」の場合は `status` を削除。
  2. ページネーションをページ1にリセット。
  3. `GET /api/v1/admin/reviews?status={status}&page=1&limit=20` からフィルタ済みレビューを取得。
  4. 新しいデータでレビューテーブルを再レンダリング。
- **例外処理:** ネットワークエラー: トースト「レビューの読み込みに失敗しました。もう一度お試しください。」を表示。

### 5.2 レビュー検索入力（`txtReviewSearch` onInput）
- **トリガー:** ユーザーが検索フィールドにテキストを入力。
- **処理ロジック:**
  1. 入力をデバウンス（300ms）。
  2. URLクエリパラメータ `?search={query}` を更新。
  3. 検索クエリでAPIからフィルタ済みレビューを取得。
  4. レビューテーブルを再レンダリング。
- **例外処理:** ネットワークエラー: トーストエラーを表示。

### 5.3 レビューソート変更（`selReviewSort` onChange）
- **トリガー:** ユーザーがソートオプションを選択。
- **処理ロジック:**
  1. URLクエリパラメータ `?sort={field}&order={asc|desc}` を更新。
  2. APIからソート済みレビューを取得。
  3. レビューテーブルを再レンダリング。
- **例外処理:** 該当なし。

### 5.4 レビュー行クリック / 詳細表示（`ddlReviewActions` → "詳細表示"）
- **トリガー:** ユーザーがアクションドロップダウンの「詳細表示」または行をクリック。
- **処理ロジック:**
  1. `GET /api/v1/admin/reviews/:id` からレビューの完全データを取得。
  2. 設定済みデータでレビューモーダルを開く。
  3. ユーザー情報、製品情報、レビュー内容、モデレーションアクションを表示。
- **例外処理:** `404 NOT_FOUND`: トースト「レビューが見つかりません」を表示。

### 5.5 レビュー承認（`btnApproveReview` onClick）
- **トリガー:** ユーザーがレビュー詳細モーダルの「承認」ボタンをクリック。
- **処理ロジック:**
  1. **バックエンドディスパッチ:** `POST /api/v1/admin/reviews/:id/moderate` に `{ action: 'approve' }` を送信。
  2. **バックエンド実行:** `reviews.is_approved = true` を更新。製品の `avg_rating` と `review_count` を再計算。製品キャッシュを無効化。監査ログを記録。
  3. **実行後UI:** モーダルを閉じる。成功トースト「レビューが承認されました」を表示。レビューリストを更新。
- **例外処理:**
  - `409 CONFLICT`: トースト「レビューは既に承認済みです」を表示。
  - `403 FORBIDDEN`: トースト「権限がありません」を表示。
  - `404 NOT_FOUND`: トースト「レビューが見つかりません」を表示。
  - `500 INTERNAL_SERVER_ERROR`: トースト「問題が発生しました。もう一度お試しください」を表示。

### 5.6 レビュー却下（`btnRejectReview` onClick → 確認と理由入力）
- **トリガー:** ユーザーが「却下」ボタンをクリックし、理由を入力してから確認をクリック。
- **処理ロジック:**
  1. **UI更新:** `lblModerationReason` と `txtModerationReason` テキストエリアを表示。
  2. **クライアント側事前チェック:** 理由が空でないこと（必須）をバリデーション。最大500文字をバリデーション。
  3. **バックエンドディスパッチ:** `POST /api/v1/admin/reviews/:id/moderate` に `{ action: 'reject', reason: '...' }` を送信。
  4. **バックエンド実行:** `reviews.is_approved = false` を更新。製品統計を再計算。キャッシュを無効化。監査ログを記録。
  5. **実行後UI:** モーダルを閉じる。成功トースト「レビューが却下されました」を表示。レビューリストを更新。
- **例外処理:**
  - `400 BAD_REQUEST`: インラインエラー「却下理由は必須です」を表示。
  - `409 CONFLICT`: トースト「レビューは既に却下済みです」を表示。
  - `500 INTERNAL_SERVER_ERROR`: トーストエラーを表示。

### 5.7 レビュー削除（`btnDeleteReview` onClick）
- **トリガー:** ユーザーがレビュー詳細モーダルの「削除」ボタンをクリック。
- **処理ロジック:**
  1. **確認ダイアログ:** 「このレビューを完全に削除してもよろしいですか？この操作は取り消せません。」を表示。
  2. **バックエンドディスパッチ:** `DELETE /api/v1/admin/reviews/:id`。
  3. **バックエンド実行:** データベースからレビューをハード削除。残りの承認済みレビューから製品の `avg_rating` と `review_count` を再計算。製品キャッシュを無効化。監査ログを記録。
  4. **実行後UI:** モーダルを閉じる。成功トースト「レビューが削除されました」を表示。レビューリストを更新。
- **例外処理:**
  - `404 NOT_FOUND`: トースト「レビューが見つかりません」を表示。
  - `500 INTERNAL_SERVER_ERROR`: トーストエラーを表示。

### 5.8 一括承認（`btnBulkApprove` onClick）
- **トリガー:** ユーザーが複数のレビューを選択して「選択を承認」をクリック。
- **処理ロジック:**
  1. **確認ダイアログ:** 「選択した{count}件のレビューを承認しますか？」を表示。
  2. **バックエンドディスパッチ:** `POST /api/v1/admin/reviews/bulk/moderate` に `{ ids: [...], action: 'approve' }` を送信。
  3. **バックエンド実行:** すべての選択済みレビューの `is_approved` を一括更新。影響を受ける製品の統計を再計算。キャッシュを無効化。
  4. **実行後UI:** 成功トースト「{count}件のレビューが承認されました」を表示。リストを更新。選択を解除。
- **例外処理:** 部分失敗: 成功/失敗した操作数を含むトーストを表示。

### 5.9 一括却下（`btnBulkReject` onClick）

  2. **バックエンドディスパッチ:** `POST /api/v1/admin/reviews/bulk/moderate` に `{ ids: [...], action: 'reject', reason: '...' }` を送信。
  3. **バックエンド実行:** 一括更新。再計算。無効化。監査。
  4. **実行後UI:** 成功トーストを表示。リストを更新。選択を解除。
- **例外処理:** 理由が空の場合: インラインエラー「却下理由は必須です」を表示。

## 11. 特記事項・UI仕様

- **デザインシステム:** 奢華化粧品テーマ — プライマリ `#7C3AED`（パープル）、アクセント `#EC4899`（ピンク）、セカンダリ `#F3E8FF`（ラベンダー）。
- **ステータスバッジカラー:** 承認済み: `bg-green-100 text-green-800`、却下済み: `bg-red-100 text-red-800`、保留中: `bg-amber-100 text-amber-800`。
- **レスポンシブビューポートデザイン:** デスクトップでフルサイドバー、タブレットで折りたたみ、モバイルでボトムナビ。
- **アクセシビリティ:** すべてのコントロールはキーボードナビゲーション可能。ARIAラベル必須。エラーメッセージは `role="alert"` で通知必须。
- **パフォーマンス:** テーブルは初期読み込み中にスケルトンローダーを使用。ボタンは非同期操作中にスピナーを表示。モーダルは遅延読み込みを使用。
- **セキュリティ:** すべてのユーザー入力はXSS防止のためサニタイズ。管理者エンドポイントはバックエンドRBACのみで強制。
- **確認ダイアログ:** すべての破壊的アクション（レビュー削除、出品者却下）に必須。`AlertDialog` コンポーネントを使用。
