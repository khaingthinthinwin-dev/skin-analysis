## 2. 画面概要・目的

### 2.1 目的
レビュー＆コンテンツ管理画面は、プラットフォームの整合性維持のための中心的な管理ハブとして機能します。管理者は製品レビューのモデレーション（承認/却下/削除/報告）、出品者登録の管理（承認/却下）、製品コンテンツのモデレーション（有効化/無効化）、ユーザーアカウントのモデレーション（有効化/無効化）が可能です。すべてのアクションは管理者専用RBACで保護されています。

### 2.2 対象ユーザーと権限

| 属性 | 値 |
| :--- | :--- |
| **主アクター** | プラットフォーム管理者（管理者） |
| **必要認証** | `admin` ロールを含むJWT Bearer Token |
| **データ範囲** | 全レビュー、製品、出品者、ユーザーアカウント |
| **アクセス制御** | 保護ルート — `JwtAuthGuard` + `RolesGuard` (`admin`) |

### 2.3 主要機能・基本設計方針
1. **レビューモデレーション** — レビューは管理者承認モデルに従います：すべてのレビューは管理者承認まで非表示。管理者は監査ログ付きでレビューを承認、却下、削除、報告が可能です。購入者は疑わしいレビューを報告することもできます。
2. **コンテンツモデレーション** — 全製品を表示し、違反コンテンツを無効化（`is_active = false`）、製品を再有効化し、プラットフォームポリシーを適用（UC-MOD-004, BR-MOD-010~013）。
3. **出品者登録管理** — 出品者ショップの登録を承認または却下。
4. **ユーザーアカウントモデレーション** — 全ユーザーを表示し、ポリシー違反によるユーザーアカウントを有効化/無効化（UC-MOD-006, BR-MOD-040~042）。管理者は自分自身を無効化できません。
5. **リアルタイムフィードバック** — すべてのモデレーションアクションに対するトースト通知。
6. **確認ダイアログ** — すべての破壊的アクション（削除、却下、無効化）に必要。
7. **ページネーション＆フィルタリング** — サーバーサイドページネーション付きタブベースステータスフィルタ。
8. **国際化** — EN、JA、MYに対する完全なi18nサポート。

### 2.4 レビュー表示フロー（管理者承認）

```text
購入者がレビューを投稿
         ↓
┌────────────────────────┐
│ レビュー作成            │
│ (is_approved = false)  │
│ 購入者に非表示         │
└────────────────────────┘
         ↓
┌────────────────────────┐
│ 管理者が保留中キューで  │
│ 確認                   │
└────────────────────────┘
         ↓
    ┌────┴────┐
    │         │
    ↓         ↓
┌───────┐ ┌───────┐
│承認   │ │却下   │
└───────┘ └───────┘
    │         │
    ↓         ↓
┌────────┐ ┌────────┐
│全員に   │ │非表示  │
│表示     │ │        │
└────────┘ └────────┘
```

**購入者報告フロー：**
```text
購入者が疑わしいレビューを確認
       ↓
   「報告」をクリック
       ↓
   理由を選択（spam/inappropriate/fake/other）
       ↓
   報告が管理者キューに送信
       ↓
   管理者が報告を確認 → レビューを却下 → 報告が解決
```

```json
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "totalPages": 8
  }
}
```

**レスポンスルール：**
- データを常に`{ data: ... }`エンベロープでラップ。
- ページネーションメタデータに`meta`を使用。
- すべての日付にISO 8601を使用: `"2026-08-21T12:00:00.000Z"`。

## 9. 権限・アクセス制御

### 9.1 ロールベースアクセス制御

| リソース | アクション | 必須ロール | 実装 |
|---------|----------|----------|------|
| レビュー一覧 | 読み取り | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| レビューモデレーション | 更新 | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| レビュー削除 | 削除 | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| 出品者一覧 | 読み取り | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| 出品者承認 | 更新 | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| ユーザー一覧 | 読み取り | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| ユーザー有効化/無効化 | 更新 | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| 報告一覧 | 読み取り | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |
| 報告ステータス更新 | 更新 | 管理者 | `JwtAuthGuard` + `RolesGuard('admin')` |

### 9.2 アクセス制御の実装

```typescript
// NestJSガード例

@Roles('admin')

export class AdminController {
  // ...
}
```

## 10. リアルタイム通知動作

### 10.1 通知トリガー

| アクション | 通知タイプ | 通知先 | メッセージ |
|---------|----------|--------|-----------|

| 出品者承認 | `merchant.approved` | 出品者ユーザー | "Your merchant account has been approved" |

## 11. 非機能的考慮事項

### 11.1 パフォーマンス

- サーバーサイドページネーションで大量データを処理
- Redisキャッシュで頻繁にアクセスされる製品データをキャッシュ
- デバウンス付き検入力でAPI呼び出しを最適化

### 11.2 セキュリティ

- JWT認証で管理者アクセスを保護
- RBACで管理者ロールのみを許可
- 監査ログですべてのモデレーションアクションを追跡

### 11.3 可用性

- 確認ダイアログで誤ったアクションを防止
- トースト通知でアクション結果を即座にフィードバック
- レスポンシブデザインでデバイスを問わずアクセス可能
