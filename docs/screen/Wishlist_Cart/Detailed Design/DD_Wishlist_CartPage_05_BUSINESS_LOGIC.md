## 1. Overview

This document specifies the core business logic, stock validation, price calculation, and state transition rules implemented in the `WishlistService` and `CartService`.

- **Wishlist Service Location:** `backend/src/modules/buyer/wishlist/wishlist.service.ts`
- **Cart Service Location:** `backend/src/modules/buyer/cart/cart.service.ts`

**Key Design Decisions:**
- All monetary values are handled as `string` (Prisma `Decimal` serialization) throughout the service layer; arithmetic is done with `parseFloat(...)` and serialized back via `.toFixed(2)` (subtotals) or `.toString()` (unit prices).
- All entity IDs use UUID v4 format per DATABASE_SPEC §1.4.
- The `canCheckout` summary flag is derived from `hasOutOfStock`, `hasQuantityExceeded`, and `hasInactive` per 機能設計書 §7.6 / BR-CART-011. It is informational only — the Cart UI does **not** use it to disable checkout.
- Response objects are assembled **inline** in each service method. There are no exported helper functions (e.g. `calculateSubtotal`, `calculateCartSummary`) and no injectable configuration object.
- Stock status is a derived display value computed by a **private** method on each service that returns a plain `string` literal. There is no backend `StockStatus` enum; the only typed union is the frontend `StockStatus` type.
- Error bodies are produced by the global `AllExceptionsFilter` (`backend/src/common/filters/http-exception.filter.ts`). A custom `errorCode` on the thrown response is honored; otherwise the HTTP status is mapped to a code from the shared `ERROR_CODES` map (`backend/src/common/constants/error-codes.ts`).

## 2. Core Service Methods — Wishlist

### 2.1 addToWishlist(userId, dto)

The controller passes a `{ productId }` object (an `AddToWishlistDto`). Steps execute in this order:

1. **Product lookup:** `product.findUnique({ where: { id: dto.productId } })`.
   - Not found → `NotFoundException('Product not found')` (404).
   - `!product.isActive` → `NotFoundException('Product is not available')` (404).
2. **Uniqueness:** `wishlist.findUnique({ where: { userId_productId: { userId, productId } } })`.
   - Exists → `ConflictException('Product already in wishlist')` (409). *(Checked before the item limit.)*
3. **Wishlist limit:** `wishlist.count({ where: { userId } })`.
   - `count >= 100` → `BadRequestException('Wishlist limit reached (100 items)')` (400). The limit is a **hardcoded `100`** (no env/config).
4. **Insert:** `wishlist.create({ data: { userId, productId } })`. The `id` is auto-generated by PostgreSQL (`gen_random_uuid()`); `createdAt` is DB-populated.
5. **Return** an item-shaped object: `id`, `productId`, `productName`, `productSlug`, `productImage` (`images[0]` or `null`), `productPrice` (string), `compareAtPrice` (string or `null`), `stockStatus`, `isInStock`, `createdAt`. **Note:** the add response does **not** include `category` (only the list response does).

- **Transaction Boundaries:** None (single insert).

### 2.2 removeFromWishlist(userId, productId)

1. **Lookup:** `wishlist.findFirst({ where: { userId, productId } })`.
   - Not found → `NotFoundException('Wishlist item not found')` (404).
2. **Delete:** `wishlist.delete({ where: { id: item.id } })`.
3. **Return** `{ success: true }`. The controller maps this to **`204 No Content`**, so the body is discarded.

- **Transaction Boundaries:** None (single delete).
- No audit/event logging is performed.

### 2.3 getWishlistItems(userId)

1. **Normalize userId:** `String(userId ?? '').trim()`.
   - If empty or equal to `'undefined'` → return `{ items: [], totalCount: 0 }` **without querying**.
2. **Query:** `wishlist.findMany({ where: { userId }, include: { product: { select: { id, name, slug, images, price, compareAtPrice, stockQuantity, isActive, category: { select: { id, name, slug } } } } }, orderBy: { createdAt: 'desc' } })`.
3. **Map** each row to an item object:
   - `id`, `productId`, `productName`, `category` (`product.category?.name ?? 'Uncategorized'`), `productSlug`, `productImage` (`images[0]` or `null`), `productPrice` (string), `compareAtPrice` (string or `null`), `stockStatus`, `isInStock` (`stockQuantity > 0`), `createdAt`.
4. **Return** `{ items, totalCount }` where `totalCount = items.length`.

- **Transaction Boundaries:** None (read-only).
- The result is a plain object, not a `WishlistItemResponseDto` class instance.

### 2.4 moveToCart(userId, productId)

1. **Wishlist lookup:** `wishlist.findFirst({ where: { userId, productId } })`.
   - Not found → `NotFoundException('Wishlist item not found')` (404).
2. **Product lookup:** `product.findUnique({ where: { id: productId } })`.
   - `!product || !product.isActive` → `NotFoundException('Product not found or unavailable')` (404).
3. **Stock check:** `product.stockQuantity <= 0` → `BadRequestException('Product is out of stock')` (400, `VAL_001`).
4. **Resolve cart:** `cart.upsert({ where: { userId }, create: { userId }, update: {} })`.
5. **Duplicate check:** `cartItem.findFirst({ where: { cartId, productId } })`.
   - **Exists → `ConflictException('This product is already in cart.')` (409, `RES_003`).** The quantity is **not** incremented and **no** merge occurs.
   - Otherwise → `cartItem.create({ data: { cartId, productId, quantity: 1 } })`.
6. **Delete the wishlist row** (`wishlist.delete({ where: { id: wishlistItem.id } })`).
7. **Return** `{ cartItem: { id, productId, productName, productSlug, productImage, unitPrice, quantity, subtotal, stockQuantity, stockStatus, isAvailable }, wishlistRemoved: true }`.

- **Transaction Boundaries:** **None.** The cart insert and the wishlist delete are separate operations and are **not** wrapped in a Prisma transaction. (There is no `$transaction` in this method.)
- There is **no** cart item-count cap and **no** initial-quantity-vs-stock check.

### 2.5 clearAllWishlist(userId)

1. **Delete all:** `wishlist.deleteMany({ where: { userId } })`.
2. **Return** `{ success: true, deletedCount: result.count }` (200 OK, BR-WISH-009).

- **Transaction Boundaries:** None (single bulk delete).

## 3. Core Service Methods — Cart

### 3.1 addToCart(userId, dto)

1. **Product lookup:** `product.findUnique({ where: { id: dto.productId } })`.
   - Not found → `NotFoundException('Product not found')` (404).
   - `!product.isActive` → `NotFoundException('Product is not available')` (404).
   - `product.stockQuantity <= 0` → `BadRequestException('Product is out of stock')` (400).
2. **Resolve cart:** `cart.upsert({ where: { userId }, create: { userId }, update: {} })`.
3. `quantity = dto.quantity || 1` (defaults to `1`).
4. **Duplicate check:** `cartItem.findFirst({ where: { cartId, productId } })`.
   - **Exists → `ConflictException('This product is already in cart.')` (409).** Quantity is **not** merged/incremented.
5. **Insert:** `cartItem.create({ data: { cartId, productId, quantity } })`.
6. **Return** the item object: `id`, `productId`, `productName`, `productSlug`, `productImage`, `unitPrice`, `quantity`, `subtotal`, `stockQuantity`, `stockStatus`, `isAvailable` (`stockQuantity >= quantity`).

- **Transaction Boundaries:** None (single insert).
- There is **no** cart item-count cap, **no** merge path, and **no** initial quantity-vs-stock validation — a request whose quantity exceeds stock still succeeds and yields `isAvailable: false`.

### 3.2 updateQuantity(userId, cartItemId, dto)

1. **Lookup (with ownership):** `cart.findUnique({ where: { userId }, include: { items: { where: { id: cartItemId }, include: { product: true } } } })`.
   - `!cart || cart.items.length === 0` → `NotFoundException('Cart item not found')` (404).
2. Take `item = cart.items[0]`.
3. **Stock check:** `dto.quantity > item.product.stockQuantity` → `BadRequestException('Only {stockQuantity} available in stock')` (400, `VAL_001`).
4. **Update:** `cartItem.update({ where: { id: cartItemId }, data: { quantity: dto.quantity } })`.
5. **Return** the item object with the new `quantity`, recomputed `subtotal`, `stockStatus`, and `isAvailable`.

- **Transaction Boundaries:** None (single update).
- The lower/upper quantity bounds (`≥ 1`, `≤ 99`) are enforced by `UpdateCartQuantityDto` before the service is called.

### 3.3 removeFromCart(userId, cartItemId)

1. **Lookup (with ownership):** `cart.findUnique({ where: { userId }, include: { items: { where: { id: cartItemId } } } })`.
   - `!cart || cart.items.length === 0` → `NotFoundException('Cart item not found')` (404).
2. **Delete:** `cartItem.delete({ where: { id: cartItemId } })`.
3. **Return** `{ success: true }`. The controller maps this to **`204 No Content`**.

- **Transaction Boundaries:** None (single delete).
- No audit/event logging is performed.

### 3.4 getCartItems(userId)

1. **Resolve cart:** `cart.upsert({ where: { userId }, create: { userId }, update: {} })`.
2. **Query:** `cartItem.findMany({ where: { cartId }, include: { product: { select: { id, name, slug, images, price, stockQuantity, isActive } } }, orderBy: { createdAt: 'desc' } })`. Note: the cart product select does **not** include `compareAtPrice` or `category`.
3. **Map** each item: `id`, `productId`, `productName`, `productSlug`, `productImage`, `unitPrice`, `quantity`, `subtotal` (`(parseFloat(price) * quantity).toFixed(2)`), `stockQuantity`, `stockStatus`, `isAvailable` (`isActive && stockQuantity >= quantity`).
4. **Aggregate summary:**
   - `totalItems` = Σ `quantity`.
   - `subtotal` = Σ `subtotal` as a 2-decimal string.
   - `shippingEstimate` = `'0.00'` (fixed).
   - `total` = `subtotal + shippingEstimate` as a 2-decimal string.
   - `hasOutOfStock` = any `stockQuantity <= 0`.
   - `hasQuantityExceeded` = any `quantity > stockQuantity`.
   - `hasInactive` = any `!isAvailable && stockQuantity > 0` (i.e. inactive but in-stock).
   - `canCheckout` = `!hasOutOfStock && !hasQuantityExceeded && !hasInactive && items.length > 0`.
5. **Return** `{ items, summary }`.

- **Transaction Boundaries:** None. The `upsert` is a single write followed by a read.

### 3.5 clearCart(userId)

1. **Lookup:** `cart.findUnique({ where: { userId } })`.
   - Not found → return `{ success: true, deletedCount: 0 }` (no error).
2. **Delete all:** `cartItem.deleteMany({ where: { cartId } })`.
3. **Return** `{ success: true, deletedCount: result.count }` (200 OK, BR-CART-012).

- **Transaction Boundaries:** None (single bulk delete).

## 4. Stock Validation Logic

### 4.1 Stock Status Calculation

Stock status is computed by a **private** method duplicated in both services. It returns a plain `string` literal, uses a hardcoded threshold of `10`, and is **not** exported. There is no backend `StockStatus` enum.

```typescript
private calculateStockStatus(stockQuantity: number): string {
  if (stockQuantity <= 0) return 'OUT_OF_STOCK';
  if (stockQuantity <= 10) return 'LOW_STOCK';
  return 'IN_STOCK';
}
```

The corresponding frontend type is declared in `frontend/src/types/wishlist-cart.types.ts`:

```typescript
export type StockStatus = 'IN_STOCK' | 'LOW_STOCK' | 'OUT_OF_STOCK';
```

### 4.2 Stock Validation Points

| Operation | Validation Point | Behavior on Failure |
|-----------|------------------|---------------------|
| Add to Cart | `stockQuantity > 0` before insert | Reject `400 VAL_001` — `"Product is out of stock"`. Initial quantity is **not** validated against stock; the response can return `isAvailable: false`. |
| Add to Cart (duplicate) | Product not already in cart | Reject `409 RES_003` — `"This product is already in cart."` |
| Update Quantity | `dto.quantity <= stockQuantity` | Reject `400 VAL_001` — `"Only {stock} available in stock"` |
| Move to Cart | `stockQuantity > 0` before cart insert | Reject `400 VAL_001` — `"Product is out of stock"`; duplicate → `409 RES_003` |
| View Cart | Stock re-derived on read | Sets `hasOutOfStock` / `hasQuantityExceeded` / `hasInactive`; no error is thrown |

### 4.3 Stock Thresholds

| Threshold | Value | Configurable | Description |
|-----------|-------|:------------:|-------------|
| Low-stock threshold | `10` | **No** — hardcoded literal in `calculateStockStatus` | Stock quantity at/below which `LOW_STOCK` is reported. The `Product.lowStockThreshold` column exists but is **not** used by this module. |
| Out-of-stock threshold | `0` | **No** | `stockQuantity <= 0` is `OUT_OF_STOCK`. |
| Max quantity per item | `99` | **No** — enforced by `@Max(99)` on `AddToCartDto` / `UpdateCartQuantityDto` | Not env-driven. |
| Wishlist max items | `100` | **No** — hardcoded in `addToWishlist` | `count >= 100`. |
| Cart max items | — | n/a | **Not enforced** anywhere. |

## 5. Price Calculation Logic

### 5.1 Subtotal Calculation

Monetary values are handled as `string` to align with Prisma's `Decimal` serialization. Subtotal is computed **inline** in each service method (there is no exported `calculateSubtotal`):

```typescript
const subtotal = (
  parseFloat(product.price.toString()) * quantity
).toFixed(2);
```

### 5.2 Cart Summary Calculation

The summary is computed inline in `CartService.getCartItems` and returned under `summary`:

```typescript
const totalItems = cartItems.reduce((sum, item) => sum + item.quantity, 0);
const subtotal = cartItems
  .reduce((sum, item) => sum + parseFloat(item.subtotal), 0)
  .toFixed(2);
const shippingEstimate = '0.00';
const total = (parseFloat(subtotal) + parseFloat(shippingEstimate)).toFixed(2);
const hasOutOfStock = cartItems.some((item) => item.stockQuantity <= 0);
const hasQuantityExceeded = cartItems.some(
  (item) => item.quantity > item.stockQuantity,
);
const hasInactive = cartItems.some(
  (item) => !item.isAvailable && item.stockQuantity > 0,
);
const canCheckout =
  !hasOutOfStock && !hasQuantityExceeded && !hasInactive && cartItems.length > 0;
```

`hasQuantityExceeded` and `hasInactive` are **not** returned to the client; only `totalItems`, `subtotal`, `shippingEstimate`, `total`, `hasOutOfStock`, and `canCheckout` are (matching 機能設計書 §7.6).

### 5.3 Pricing Rules

| Rule | Description | Enforcement |
|------|-------------|-------------|
| Price at Order Time | Price is locked at order creation time, not cart time. | Order service |
| No Discounts on Cart | Subtotal = `unit_price × quantity`. Discounts/coupons applied at checkout. | Frontend + Backend |
| Currency Format | Price displayed with locale-appropriate formatting. | Frontend (i18n) |
| Decimal Serialization | All monetary fields returned as strings (e.g., `"29.99"`) per Prisma Decimal behavior. | Backend DTOs |

## 6. State Transition Logic

`stockStatus` (`IN_STOCK` / `LOW_STOCK` / `OUT_OF_STOCK`) is a **derived display value** recomputed on every read; there is no persisted state machine. The transitions below describe the observable item lifecycle.

### 6.1 Wishlist State Transitions

| Transition | Origin | Target | Trigger | Guard Conditions |
|------------|--------|--------|---------|------------------|
| TR-WISH-01 | — | `SAVED` | `addToWishlist()` | Authenticated, product exists and active, not already in wishlist, count < 100 |
| TR-WISH-02 | `SAVED` | — | `removeFromWishlist()` | User owns wishlist item |
| TR-WISH-03 | `SAVED` | — | `clearAllWishlist()` | User owns wishlist (bulk) |
| TR-WISH-04 | `SAVED` | `MOVED_TO_CART` | `moveToCart()` | Product active and `stockQuantity > 0`, not already in cart |
| TR-WISH-05 | any | `OUT_OF_STOCK` (derived) | Read | `stockQuantity <= 0` |

### 6.2 Cart State Transitions

| Transition | Origin | Target | Trigger | Guard Conditions |
|------------|--------|--------|---------|------------------|
| TR-CART-01 | — | `ACTIVE` | `addToCart()` | Authenticated, product active, `stockQuantity > 0`, not already in cart |
| TR-CART-02 | `ACTIVE` | `ACTIVE` | `updateQuantity()` | `requestedQuantity <= stockQuantity` |
| TR-CART-03 | `ACTIVE` | `QUANTITY_EXCEEDED` (derived) | Read | `quantity > stockQuantity` |
| TR-CART-04 | `ACTIVE` | `OUT_OF_STOCK` (derived) | Read | `stockQuantity <= 0` |
| TR-CART-05 | `ACTIVE` | — | `removeFromCart()` | User owns cart item |
| TR-CART-06 | `ACTIVE` | — | `clearCart()` | User owns cart (bulk) |

## 7. Duplicate Handling Logic

Both services reject duplicates with a plain `ConflictException` (no custom error object). The global filter maps `409` → `RES_003`. **No merge/increment occurs in either path.**

### 7.1 Wishlist Uniqueness

```typescript
const existing = await this.prisma.wishlist.findUnique({
  where: {
    userId_productId: {
      userId,
      productId: dto.productId,
    },
  },
});

if (existing) {
  throw new ConflictException('Product already in wishlist');
}
```

The database also enforces the `[user_id, product_id]` unique constraint as a final safety net.

### 7.2 Cart / Move-to-Cart Duplicate Handling

Both `CartService.addToCart` and `WishlistService.moveToCart` check for an existing cart item and throw `409` rather than merging:

```typescript
const existingItem = await this.prisma.cartItem.findFirst({
  where: { cartId: cart.id, productId },
});

if (existingItem) {
  throw new ConflictException('This product is already in cart.');
}
```

The frontend matches this exact message (`"This product is already in cart."`) to open the `DuplicateCartAlertDialog`.

## 9. Rate Limiting Logic

There is **no** per-endpoint rate limiting for wishlist/cart operations. The keys `rate:wish-cart:*` and the per-endpoint limits are **not** implemented.

The only relevant mechanism is the global `RateLimitInterceptor` (`backend/src/common/interceptors/rate-limit.interceptor.ts`), registered in `main.ts`. It:

- Uses a **15-minute window**, with `maxRequests = 100` by default and `10` for paths containing `/auth/login` or `/auth/register`.
- Keys buckets as `ratelimit:{ip}:{path}` in Redis.
- **Only adds informational headers** (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`, `X-RateLimit-Policy`) after the handler completes; it does **not** count or reject requests, so these endpoints do **not** return `429` from this interceptor.
- Fails silently if Redis is unavailable.

If a `429` is ever surfaced, the global filter maps it to `RATE_001`.

## 11. Validation Rules

### 11.1 Wishlist Validation

| Field | Rule | Error Message |
|-------|------|---------------|
| `productId` (body) | Required, valid UUID v4 (`AddToWishlistDto`, `@IsUUID('4')`) | `"Product ID is required"` / `"Invalid product ID format"` |
| `productId` (route) | Raw string; path DTO is **not** wired, so UUID format is not validated | — |
| — | Product must exist | `"Product not found"` (404) |
| — | Product must be active | `"Product is not available"` (404) |
| — | Product must not already be in wishlist | `"Product already in wishlist"` (409) |
| — | Wishlist count < 100 | `"Wishlist limit reached (100 items)"` (400) |

### 11.2 Cart Validation

| Field | Rule | Error Message |
|-------|------|---------------|
| `productId` | Required, valid UUID v4 (`AddToCartDto`) | `"Product ID is required"` / `"Invalid product ID format"` |
| `quantity` | Optional, integer 1–99 (`AddToCartDto`) | `"Quantity must be at least 1"` / `"Quantity cannot exceed 99"` |
| `quantity` | Required, integer 1–99 (`UpdateCartQuantityDto`) | `"Quantity must be at least 1"` / `"Quantity cannot exceed 99"` |
| — | Product must exist | `"Product not found"` (404) |
| — | Product must be active | `"Product is not available"` (404) |
| — | Product must have stock > 0 | `"Product is out of stock"` (400) |
| — | Product must not already be in cart | `"This product is already in cart."` (409) |
| — | Requested quantity ≤ product stock (update only) | `"Only {n} available in stock"` (400) |

### 11.3 Move to Cart Validation

| Field | Rule | Error Message |
|-------|------|---------------|
| `productId` | Product must be in the user's wishlist | `"Wishlist item not found"` (404) |
| — | Product must exist and be active | `"Product not found or unavailable"` (404) |
| — | Product `stockQuantity > 0` | `"Product is out of stock"` (400) |
| — | Product must not already be in cart | `"This product is already in cart."` (409) |

> **Path parameters are not DTO-validated.** The wishlist and cart-item path params (`:productId`, `:id`) are read as raw strings; UUID format errors surface as `404`/`409` from the service rather than `400`.

## 12. Error Response Structure

Bodies are produced by the global `AllExceptionsFilter`. The `error` field is the NestJS HTTP status text (e.g. `"Bad Request"`, `"Conflict"`), and `errorCode` is either the custom code from the thrown response or the status-mapped default.

```json
{
  "statusCode": 400,
  "error": "Bad Request",
  "errorCode": "VAL_001",
  "message": "Only 2 available in stock",
  "timestamp": "2026-08-23T12:00:00.000Z",
  "path": "/api/v1/cart/items/9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d"
}
```

When DTO validation fails, `message` is an array of strings and a `details.validationErrors` object is added.

### 12.1 Error Code Reference (codes surfaced by this module)

| Error Code | HTTP Status | Scenario |
|------------|-------------|----------|
| `VAL_001` | 400 | DTO validation failure, out of stock, quantity exceeds stock, wishlist limit reached |
| `AUTH_001` / `AUTH_002` / `AUTH_003` | 401 | Missing, invalid, or expired JWT |
| `RES_004` | 403 | Authenticated user is not a `buyer` |
| `ACCOUNT_DEACTIVATED` | 403 | `ActiveUserGuard` rejects a deactivated account (custom code thrown by the guard) |
| `RES_001` | 404 | Product, wishlist item, or cart item not found / inactive |
| `RES_003` | 409 | Product already in wishlist or cart |
| `RATE_001` | 429 | Only if a `429` is thrown elsewhere; **not** produced by these endpoints |
| `SYS_001` | 500 | Unhandled server error |

All codes are defined in the shared `ERROR_CODES` map (`backend/src/common/constants/error-codes.ts`). `ACCOUNT_DEACTIVATED` is a literal emitted directly by `ActiveUserGuard`, not part of that map.

## 13. Security Considerations

| Concern | Mitigation |
|---------|------------|
| Unauthorized access | JWT Bearer token validation on all endpoints |
| Price manipulation | Price fetched from DB, never client-provided |
| Stock manipulation | Stock validated server-side before operations |
| IDOR attacks | Ownership validation: wishlist filtered by `userId` from JWT; cart items reached only via the user's own `cart.id` |
| Race conditions on stock | Stock validated server-side before operations; the unique `[user_id, product_id]` constraint guards duplicate wishlist inserts. **Note:** `moveToCart` and `addToCart` are not wrapped in an explicit Prisma transaction. |
| Deactivated accounts | `ActiveUserGuard` on `POST /wishlist/:productId`, `POST /wishlist/:productId/move-to-cart`, and `POST /cart/items` |
| RBAC enforcement | `@Roles('buyer')` on all wishlist/cart controllers per DEVELOPMENT_RULES §5.4 |
