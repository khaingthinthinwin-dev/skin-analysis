## 1. 機能概要

### 1.1 目的と範囲

本画面は、Cosmetics Finderプラットフォーム向けのお気に入り（Wishlist）およびショッピングカート（Cart）の完全な機能を提供する。お気に入りサブシステムは、認証済みユーザーが将来の参考のために商品を保存できるようにし、カートサブシステムは商品選択からチェックアウト開始に至る購入ワークフロー全体を管理する。

これらのサブシステムは、商品閲覧と注文確定を橋渡しするeコマースワークフローの極めて重要な構成要素である。シームレスな商品リスト管理、数量変更、在庫検証、価格計算を支援し、円滑な購入体験を実現する。

### 1.2 機能責務

本画面は以下のコア機能領域を担当する：

1. **お気に入り管理** — 認証済みユーザーがお気に入りに商品を追加/削除し、保存した商品の詳細を表示し、カートへ移動できるようにする。
2. **ショッピングカート管理** — 認証済みユーザーがカートに商品を追加し、数量を更新し、商品を削除し、リアルタイムで小計を確認できるようにする。
3. **在庫検証** — カート追加前の在庫有無の確認、および数量更新時の在庫検証を行う。
4. **価格計算** — 各カート商品の単価 × 数量に基づく小計を計算する。割引およびクーポンはカート画面では**適用されない**。クーポン入力および割引計算はチェックアウト画面で行われる。
5. **お気に入りからカートへの移動** — 保存したお気に入り商品をショッピングカートへ直接移動できるようにする。
6. **カート永続化** — ログインユーザーのセッション間でカート内容をデータベース保存により維持する。
7. **商品表示** — お気に入りおよびカート表示の両方で、商品画像、商品名、価格、在庫ステータスを表示する。

### 1.3 対象ユーザー

| 属性 | 値 |
|------|-----|
| **主要アクター** | 認証済みバイヤー (Authenticated Buyer) |
| **認証要件** | JWTベアラートークン |
| **データスコープ** | 自身の所属するお気に入り商品、自身のカート商品 |
| **ゲストユーザーの動作** | カートは永続化されず、お気に入りは利用不可。ゲストユーザーがカートアクションをクリックした場合、アラートモーダル「カートに商品を追加するにはログインしてください。」が表示される。お気に入りアクションをクリックした場合、アラートモーダル「お気に入りに追加するにはログインしてください。」が表示される。いずれのモーダルでも[ログイン]をクリックすると`/login`に遷移する。 |

### 2.4 ワークフロークリティカルパス概要

| ステップ | アクション | 処理前ステータス | 処理後ステータス | 担当 |
|:----:|--------|---------------|--------------|-------------|
| 1 | ユーザーが商品で「お気に入りに追加」をクリック | 未保存 | お気に入りアイテム作成完了 | システム |
| 2 | ユーザーがハートアイコンを再クリックして解除 | 保存済み | お気に入りアイテム削除完了 | システム |
| 3 | ユーザーが `/wishlist` に遷移 | — | お気に入り画面表示完了 | システム |
| 4 | ユーザーがお気に入りから「カートへ移動」をクリック | お気に入り内に存在 | カートアイテム作成完了 | システム |
| 5 | ユーザーが商品で「カートに追加」をクリック | カート内に未存在 | カートアイテム作成完了 | システム |
| 6 | ユーザーがカート内で数量を変更 | 変更前数量 | 新規数量、小計更新完了 | システム |
| 7 | ユーザーがカートからアイテムを削除 | カート内に存在 | カートアイテム削除完了 | システム |
| 8 | ユーザーが `/cart` に遷移 | — | カート画面表示完了 | システム |

### 2.5 カバーする関連要件

| 要件ID | 要件概要 |

| B-WISH-001 | ユーザーは商品をお気に入りに追加できる |

| B-WISH-003 | ユーザーはお気に入り一覧を表示できる |
| B-WISH-004 | お気に入りには商品画像、価格、在庫状況が表示される |
| B-WISH-005 | ユーザーはお気に入りアイテムをカートへ移動できる |
| B-CART-001 | ユーザーは商品をカートに追加できる |
| B-CART-002 | ユーザーはアイテムの数量を更新できる |
| B-CART-003 | ユーザーはカートからアイテムを削除できる |
| B-CART-004 | カートにはアイテムごとの小計計算が表示される |
| B-CART-005 | カートには有効在庫数が表示される |
| B-CART-006 | ログインユーザーのカートはセッション間で永続化される |
| B-CART-007 | カートには商品画像と商品名が表示される |

**プロモーション・割引に関する特記:** カート画面には割引適用前の小計（単価 × 数量）のみが表示される。クーポンコードの入力および割引計算（要件定義書 `要件定義書_REQUIREMENT_SPEC.md` のルール 4.5.1 および 4.5.2 に準拠）はチェックアウト画面（`/checkout`）で処理され、カート画面では行われない。この分離により、チェックアウト前のシンプルな確認ステップとしてカートを維持する。

**ゲストユーザーの動作に関する特記:** 未認証（ゲスト）ユーザーはカートおよびお気に入りの操作を行えない。カート操作時は「カートに商品を追加するにはログインしてください。」、お気に入り操作時は「お気に入りに追加するにはログインしてください。」のアラートモーダルが表示される。いずれのモーダルでも[ログイン]をクリックすると`/login`に遷移する。モーダル表示前に直接リダイレクトされることはない。

## 6. 機能操作仕様

### 6.1 操作：お気に入りに商品追加

| 属性 | 仕様 |
|-----------|---------------|
| **トリガー** | 商品カード/詳細のハートアイコンクリックまたは「お気に入り追加」ボタンクリック |
| **APIエンドポイント** | `POST /api/v1/wishlist/:productId` |
| **リクエストヘッダー** | `Authorization: Bearer <accessToken>` |
| **ゲスト動作** | API呼び出し前に「お気に入りに追加するにはログインしてください。」の`wishlist.guestLoginAlert`を表示し、[ログイン]クリック時のみ`/login`へ遷移。 |
| **送信前バリデーション** | ユーザーが`buyer`ロールで認証済みであること、商品が存在し有効であること |
| **処理ステップ** | 1. JWTトークンおよび`buyer`ロールを検証。 2. 商品の存在と`isActive = true`を確認。 3. すでにユーザーのお気に入りに存在するか確認。 4. 存在しない場合、お気に入りレコードを作成。 5. 標準レスポンスエンベロープを返却。 6. `WISHLIST_ITEM_ADDED` を記録。 |
| **成功レスポンス** | 201 Created（お気に入りアイテムデータを含む） |
| **事後アクション** | ハートアイコンを塗りつぶし状態に切り替え |

### 6.2 操作：お気に入りから商品削除

| 属性 | 仕様 |
|-----------|---------------|
| **トリガー** | ハートアイコンの再クリック（解除）またはお気に入り画面の「削除」ボタンクリック |
| **APIエンドポイント** | `DELETE /api/v1/wishlist/:productId` |
| **リクエストヘッダー** | `Authorization: Bearer <accessToken>` |
| **ゲスト動作** | API呼び出し前に`wishlist.guestLoginAlert`を表示し、[ログイン]クリック時のみ`/login`へ遷移。 |
| **送信前バリデーション** | ユーザーが`buyer`ロールで認証済みであること、商品がユーザーのお気に入りに存在すること |
| **処理ステップ** | 1. JWTトークンおよび`buyer`ロールを検証。 2. `userId` + `productId` でお気に入りレコードを検索。 3. 存在する場合、レコードを削除。 4. レスポンスボディなしで 204 を返却。 5. `WISHLIST_ITEM_REMOVED` を記録。 |
| **成功レスポンス** | 204 No Content |
| **事後アクション** | ハートアイコンをアウトライン状態に切り替え、お気に入り画面の場合は一覧からアイテムを削除 |

### 6.3 操作：お気に入り一覧表示

| 属性 | 仕様 |
|-----------|---------------|
| **トリガー** | `/wishlist` への画面遷移 |
| **APIエンドポイント** | `GET /api/v1/wishlist` |
| **リクエストヘッダー** | `Authorization: Bearer <accessToken>` |
| **ゲスト動作** | `/login` へ直接リダイレクトする前に`wishlist.guestLoginAlert`を表示。 |
| **送信前バリデーション** | ユーザーが`buyer`ロールで認証済みであること |
| **処理ステップ** | 1. JWTトークンおよび`buyer`ロールを検証。 2. `user_id` で`wishlists`を検索し、`created_at DESC` でソート。 3. 商品名、価格、画像、有効状態、在庫数を取得するために`products`と結合。 4. 各アイテムの在庫ステータスを導出。 5. `{ data: { items, totalCount } }` を返却。 |

| **事後アクション** | 商品カード付きのお気に入りグリッドを描画 |

| **処理ステップ** | 1. JWTトークンおよび`buyer`ロールを検証。 2. お気に入りレコードを検索。 3. 商品が有効で`stock_quantity > 0`であることを確認。 4. Prismaトランザクション内でユーザーの`cart_items`行を作成または更新。 5. すでに存在する場合は数量を加算し、新数量が在庫を超えないことを確認。 6. 同一トランザクション内でお気に入りレコードを削除。 7. `{ data: { cartItem, wishlistRemoved } }` を返却。 8. `WISHLIST_ITEM_MOVED_TO_CART` を記録。 |

### 6.8 操作：カート一覧表示

| 属性 | 仕様 |
|-----------|---------------|
| **トリガー** | `/cart` への画面遷移 |
| **APIエンドポイント** | `GET /api/v1/cart` |
| **リクエストヘッダー** | `Authorization: Bearer <accessToken>` |
| **送信前バリデーション** | ユーザーが`buyer`ロールで認証済みであること |
| **処理ステップ** | 1. JWTトークンおよび`buyer`ロールを検証。 2. ユーザーの`cart`を特定し、その`cart_items`を取得。 3. 詳細情報（商品名、slug、画像、価格、有効状態、在庫数）を取得するために`products`と結合。 4. 各アイテムの `unitPrice × quantity` を計算し、割引前の小計を合算。 5. 在庫ステータスと有効性（`stock_quantity >= quantity`）を導出。 6. すべてのアイテムが有効かつ在庫内である場合のみ `canCheckout = true` を設定（`OUT_OF_STOCK`、`QUANTITY_EXCEEDED`、`INACTIVE`、またはカートが空の場合は `false`）。 7. Decimal値を文字列としてシリアライズし、`{ data: { items, summary } }` を返却。 |
| **成功レスポンス** | 200 OK（カートアイテム一覧およびサマリーを含む） |
| **事後アクション** | アイテム一覧およびサマリーパネルを含むカート画面を描画 |

  "statusCode": 400,

### 9.2 エラー分類テーブル — お気に入り

| HTTPステータス | エラーコード | シナリオ | ユーザー向け挙動 |
|-------------|------------|----------|---------------------|
| `400` | `BAD_REQUEST` | バリデーションエラー（無効なproductId） | インラインフィールドエラー ＋ トースト |

### 9.3 エラー分類テーブル — カート

| HTTPステータス | エラーコード | シナリオ | ユーザー向け挙動 |
|-------------|------------|----------|---------------------|
| `400` | `BAD_REQUEST` | バリデーションエラー（無効な数量） | インラインフィールドエラー ＋ トースト |

- **フィールドレベルバリデーション**: 不正な入力項目の下に赤枠とインラインテキストを表示。
- **トースト通知**: APIエラーおよび成功アクション（追加、削除、更新）の通知に使用。
- **オプティミスティックUI更新**: ハートアイコンはクリック時に即時反転し、API失敗時に元の状態へ復元。
- **ローディング状態**: API処理中はボタンにスピナーを表示。画面コンテンツにはスケルトンローダーを使用。
- **在庫警告**: 在庫僅少または在庫切れのカートアイテムにインラインバッジ/アラートを表示。

## 10. 権限・アクセス制御

### 10.1 認証要件

- すべてのお気に入りおよびカートエンドポイントに対し、`Authorization`ヘッダー経由でJSON Web Token（JWT）ベアラートークンを送信。
- 全エンドポイントは `JwtAuthGuard`、`RolesGuard`、および `@Roles('buyer')` により保護される。

### 10.2 公開 vs 保護エンドポイント

| エンドポイント | アクセスレベル | 説明 |
|----------|-------------|-------------|
| `GET /wishlist` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `POST /wishlist/:productId` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `DELETE /wishlist/:productId` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `POST /wishlist/:productId/move-to-cart` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `GET /cart` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `POST /cart/items` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `PATCH /cart/items/:id` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |
| `DELETE /cart/items/:id` | 保護 (Protected) | 有効なアクセストークンおよび`buyer`ロールが必要 |

### 10.3 ロールベースアクセス

| ロール | お気に入りアクセス可 | カートアクセス可 | 備考 |
|------|:-------------------:|:---------------:|-------|
| `buyer` | ✓ | ✓ | 本機能の主要アクター |
| `merchant` | ✗ | ✗ | アクセス不可：「ショッピング機能は購入者のみ利用できます」 (403 Forbidden) |
| `admin` | ✗ | ✗ | アクセス不可：「ショッピング機能は購入者のみ利用できます」 (403 Forbidden) |

### 10.4 所有権ルール

| リソース | 所有権ルール | 適用方式 |
|----------|---------------|-------------|
| お気に入りアイテム | ユーザーは自身のお気に入りアイテムのみ閲覧/変更可能 | バックエンドでJWTの`user_id`によりフィルタリング |
| カートアイテム | ユーザーは自身の`cart.id`経由でアクセス可能なアイテムのみ閲覧/変更可能 | バックエンドでJWTの`user_id`から`cart.id`を特定し、`cart_id`でフィルタリング |

| ヘッダーカートアイコン | `/cart` | ヘッダー内のカートアイコンをクリック |
| ヘッダーハートアイコン | `/wishlist` | ヘッダー内のお気に入りアイコンをクリック |
| 任意の画面 (未認証) | `/login` | 未認証でお気に入り/カート操作をクリック（モーダル経由） |

### 12.2 内部遷移

| 流入元 | 遷移先 | トリガー |
|--------|--------|---------|
| `/wishlist` | `/products/:slug` | 商品画像または商品名をクリック |
| `/wishlist` | `/cart` | お気に入りアイテムの「カートへ移動」をクリック |
| `/cart` | `/products/:slug` | 商品画像または商品名をクリック |
| `/cart` | `/checkout` | 「チェックアウトへ進む」をクリック |
| `/cart` | `/products` | 「買い物を続ける」をクリック |

### 12.3 流出先遷移

| 流入元 | 遷移先 | 条件 |
|--------|--------|-----------|
| `/wishlist` | `/cart` | アイテムをカートへ移動 |
| `/cart` | `/checkout` | チェックアウトへ進む（全アイテム在庫あり） |
| `/cart` | `/login` | セッション期限切れ |

### 12.4 エラー時の遷移

| 流入元 | 遷移先 | 条件 |
|--------|--------|-----------|
| `/wishlist` | `/login` | 401 Unauthorized |

| 商品詳細 / 商品カード | `/login` | ゲストユーザーが「カートに追加」をクリック（アラートモーダル経由） |

### 13.1 パフォーマンス要件

| カート追加API | ≤ 300ミリ秒 |
| 数量更新API | ≤ 200ミリ秒 |
| アイテム削除API | ≤ 200ミリ秒 |
| 在庫検証チェック | ≤ 100ミリ秒 |

### 13.2 キャッシュ戦略

| キャッシュ対象 | 戦略 | TTL |
|--------------|----------|-----|
| お気に入りアイテム | キャッシュなし (ユーザー固有) | — |
| カートアイテム | キャッシュなし (ユーザー固有) | — |
| 商品詳細 | Redisキャッシュ | 5分 |
| 在庫数 | DBからリアルタイム取得 | — |

### 13.3 セキュリティ考慮事項

| 懸念事項 | 対策 |
|---------|------------|
| 不正アクセス | 全エンドポイントでのJWTベアラートークン検証 |
| 価格改ざん | クライアント提供値ではなくDBから価格を取得 |
| 在庫改ざん | 操作前にサーバー側で在庫を厳格に検証 |
| IDOR攻撃 | 所有権検証（JWTの`userId`に基づく検証） |
| 在庫の競合状態 | Prismaトランザクションによる原子的操作 |

### 13.4 レスポンシブデザイン要件

| ブレークポイント | お気に入りレイアウト | カートレイアウト |
|------------|-----------------|-------------|
| デスクトップ (≥ 1024px) | 4列グリッド | アイテム一覧 ＋ 右側サイドバーサマリー |
| タブレット (768px – 1023px) | 2列グリッド | アイテム一覧 ＋ 下部サマリー |
| モバイル (< 768px) | 1列リスト | 縦積みアイテム ＋ 下部サマリー |
