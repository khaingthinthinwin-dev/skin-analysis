## 1. Functional Overview

### 1.1 Purpose and Scope

This subsystem manages the complete lifecycle of skincare products within the Cosmetics Finder marketplace. It provides merchants with full CRUD capabilities for product listings, inventory management, and image uploads, while offering buyers advanced search, filtering, and product detail viewing.

The Product Management subsystem is central to the marketplace platform. It connects merchant inventory with buyer demand through intelligent search, category-based navigation, and AI-powered recommendations based on skin analysis results.

### 1.2 Functional Responsibilities

This subsystem is responsible for the following core functional areas:

1. **Product Creation** — Merchants can create new product listings with name, description, price, category, images, skin type compatibility, ingredients, and tags.
2. **Product Editing** — Merchants can update existing product details, images, pricing, and metadata.
3. **Product Deletion** — Merchants can soft-delete products (set `is_active = false`), hiding them from buyer searches while retaining data.
4. **Image Management** — Merchants can upload, reorder, and remove product images (max 10 images, 5MB each, JPG/PNG/WebP).
5. **Inventory Management** — Merchants can view and update stock quantities, set low stock thresholds, and receive low stock warnings.
6. **Product Browsing** — Buyers can browse active products with pagination, sort by price/rating/newest, and navigate by category tree.
7. **Product Search & Filter** — Buyers can search products by keyword with partial matching, filter by skin type, ingredients, price range, and rating.
8. **Product Detail View** — Buyers can view full product details including images, description, ingredients, reviews, ratings, and skin type compatibility.
9. **Featured Products** — Merchants can flag products as featured; featured products appear on the home page.
10. **Active/Inactive Toggle** — Merchants can toggle product visibility without deleting.

## 3. State Transition Specification

### 3.1 Product States

| State | Description | Visible to Buyers | Can Edit | Can Order |
|-------|-------------|:-----------------:|:--------:|:---------:|
| `DRAFT` | Product created but not yet active | ✗ | ✓ | ✗ |
| `ACTIVE` | Product is live and available for purchase | ✓ | ✓ | ✓ |
| `INACTIVE` | Product hidden by merchant (soft delete) | ✗ | ✓ | ✗ |
| `OUT_OF_STOCK` | Product has zero stock | ✓ (with label) | ✓ | ✗ |

| TR-PROD-03 | `INACTIVE` | `ACTIVE` | Toggle active on | Product belongs to merchant |
| TR-PROD-04 | `ACTIVE` | `OUT_OF_STOCK` | Stock decremented to 0 | Order creation |
| TR-PROD-05 | `OUT_OF_STOCK` | `ACTIVE` | Stock replenished | Merchant updates stock |
| TR-PROD-06 | `ACTIVE` | `INACTIVE` | Soft delete | Product belongs to merchant |
| TR-PROD-07 | `INACTIVE` | `ACTIVE` | Restore product | Product belongs to merchant |

## 4. Business Rules

### 4.1 Product Creation Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-001 | Required Fields | Product must have: name, categoryId, price, description. | Backend (DTO validation) + Frontend (Zod schema) |
| BR-PROD-002 | Price Positive | Price must be greater than 0. | Backend (DB constraint `chk_products_price`) |
| BR-PROD-003 | Compare Price | compareAtPrice must be greater than price (if provided). | Backend (DTO validation) |
| BR-PROD-004 | SKU Uniqueness | SKU must be unique across all products (if provided). | Backend (DB constraint `uq_products_sku`) |
| BR-PROD-005 | Slug Generation | Slug auto-generated from product name, must be unique. | Backend (slug util) |
| BR-PROD-006 | Category Existence | Category must exist and be valid. | Backend (DB FK constraint) |
| BR-PROD-007 | Default Status | New products default to `is_active = true`. | Backend (DB default) |
| BR-PROD-008 | Default Featured | New products default to `is_featured = false`. | Backend (DB default) |

### 4.2 Product Image Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-009 | Max Images | Maximum 10 images per product. | Backend (DTO validation) |
| BR-PROD-010 | File Size | Maximum 5MB per image. | Backend (file upload validation) |
| BR-PROD-011 | File Types | Allowed: JPG, PNG, WebP. | Backend (MIME type validation) |
| BR-PROD-012 | Primary Image | First image is the primary/cover image. | Frontend (display logic) |
| BR-PROD-013 | File Naming | UUID-based filenames to prevent conflicts. | Backend (upload service) |

### 4.3 Product Status Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-014 | Active Visibility | Only `is_active = true` products appear in search results. | Backend (query filter) |
| BR-PROD-015 | Inactive Hidden | Inactive products hidden from buyers but visible to merchant. | Backend (role-based query) |
| BR-PROD-016 | Soft Delete | Delete sets `is_active = false`, does not remove record. | Backend (service logic) |
| BR-PROD-017 | Featured Flag | Featured products appear on home page. | Backend (query filter) |

### 4.4 Inventory Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-018 | Stock Non-Negative | Stock quantity cannot go below 0. | Backend (DB constraint `chk_products_stock`) |
| BR-PROD-019 | Low Stock Threshold | Default threshold is 10 units. Warning when stock ≤ threshold. | Backend (service logic) |
| BR-PROD-020 | Out of Stock | Products with 0 stock cannot be added to cart. | Backend (cart validation) |
| BR-PROD-021 | Atomic Decrement | Stock decremented atomically on order creation. | Backend (DB transaction) |

### 4.5 Search & Filter Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-022 | Partial Matching | Search supports partial keyword matching. | Backend (PostgreSQL `ILIKE`) |
| BR-PROD-023 | Pagination | Default 20 items per page, configurable max 100. | Backend (query params) |
| BR-PROD-024 | Sort Options | Sort by: price_asc, price_desc, rating, newest, name. | Backend (query params) |
| BR-PROD-025 | Multi-Filter | Multiple filters can be applied simultaneously. | Backend (AND conditions) |
| BR-PROD-026 | Category Tree | Category navigation supports nested parent-child. | Backend (recursive query) |

### 4.6 Ownership Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-027 | Merchant Ownership | Merchants can only edit/delete their own products. | Backend (service check) |
| BR-PROD-028 | Admin Override | Admins can manage all products. | Backend (RBAC) |
| BR-PROD-029 | Buyer Read-Only | Buyers can only view products, not modify. | Backend (RBAC) |

### 6.1 Operation: List Products (Public)

| **Processing Steps** | 1. Validate query parameters. 2. Build Prisma WHERE clause with filters. 3. Apply pagination (default: 20 per page). 4. Sort results (default: newest). 5. Execute query with `select` for list view. 6. Return paginated response with meta. |
| **Success Response** | 200 OK with product list and pagination meta |
| **Cache** | Redis: `cache:products:list:{hash}` TTL 2 minutes |

### 6.2 Operation: Get Product Detail (Public)

| Attribute | Specification |
|-----------|---------------|
| **Trigger** | Navigate to `/products/:slug` |
| **API Endpoint** | `GET /api/v1/products/:slug` |
| **Request Content-Type** | None |
| **Pre-Submission Validation** | Slug format validated |
| **Processing Steps** | 1. Validate slug parameter. 2. Check Redis cache (`cache:product:{slug}`). 3. On cache miss: Query product with `include` (category, merchant shop, reviews). 4. Calculate avg rating and review count. 5. Cache result in Redis. 6. Return product detail DTO. |
| **Success Response** | 200 OK with full product detail |
| **Cache** | Redis: `cache:product:{slug}` TTL 5 minutes |

Check slug uniqueness. 6. Upload images (if provided). 7. Create product record in DB. 8. Invalidate product list cache. 9. Return created product DTO. |

| `/products/:slug` | `/wishlist` | Click "Add to Wishlist" (login required) |
| `/merchant/products/new` | `/merchant/products` | Product created successfully |
| `/merchant/products/:id/edit` | `/merchant/products` | Product updated successfully |

### 12.4 Error Navigation

| Any product page | `/unauthorized` | 403 Forbidden |
| Any product page | `/` | Product not found (404) |
