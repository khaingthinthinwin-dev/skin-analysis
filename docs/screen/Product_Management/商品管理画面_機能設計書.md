## 1. Functional Overview

### 1.1 Purpose and Scope

This subsystem manages the complete lifecycle of skincare products within the Cosmetics Finder marketplace. It provides merchants with full CRUD capabilities for product listings, inventory management, and image uploads.

The Product Management subsystem is central to the marketplace platform, enabling merchants to efficiently manage their product catalog, inventory, and product information.

### 1.2 Functional Responsibilities

This subsystem is responsible for the following core functional areas:

1. **Product Creation** — Merchants can create new product listings with name, description, price, category, images, skin type compatibility, ingredients, and tags.
2. **Product Editing** — Merchants can update existing product details, images, pricing, and metadata.
3. **Product Deletion** — Merchants can soft-delete products (set `is_active = false`), hiding them from searches while retaining data. **Note: Products with active orders (pending/confirmed/processing/delivered) cannot be deleted.** **Note: Products with any order in 'pending' status cannot be created, edited, updated, or deleted. All CRUD operations are restricted.**
4. **Image Management** — Merchants can upload, reorder, and remove product images (max 10 images, 5MB each, JPG/PNG/WebP).
5. **Inventory Management** — Merchants can view and update stock quantities, set low stock thresholds, and receive low stock warnings.
6. **Featured Products** — Merchants can flag products as featured; featured products appear on the home page.
7. **Active/Inactive Toggle** — Merchants can toggle product visibility without deleting.

## 3. State Transition Specification

### 3.1 Product States

| State | Description | Can Edit | Can Order |
|-------|-------------|:--------:|:---------:|
| `DRAFT` | Product created but not yet active | ✓ | ✗ |
| `ACTIVE` | Product is live and available for purchase | ✓ | ✓ |
| `INACTIVE` | Product hidden by merchant (soft delete) | ✓ | ✗ |
| `OUT_OF_STOCK` | Product has zero stock | ✓ | ✗ |

### 3.2 Product Lifecycle Transitions

| Transition ID | Origin State | Target State | Trigger Action | Guard Conditions |
|---------------|--------------|--------------|----------------|------------------|
| TR-PROD-01 | — | `ACTIVE` | Create product (default) | Valid product data, merchant authenticated |
| TR-PROD-02 | `ACTIVE` | `INACTIVE` | Toggle active off | Product belongs to merchant |
| TR-PROD-03 | `INACTIVE` | `ACTIVE` | Toggle active on | Product belongs to merchant |
| TR-PROD-04 | `ACTIVE` | `OUT_OF_STOCK` | Stock decremented to 0 | Order creation |
| TR-PROD-05 | `OUT_OF_STOCK` | `ACTIVE` | Stock replenished | Merchant updates stock |
| TR-PROD-06 | `ACTIVE` | `INACTIVE` | Soft delete | Product belongs to merchant AND no active orders (all orders in 'done' status) AND no orders in 'pending' status |
| TR-PROD-07 | `INACTIVE` | `ACTIVE` | Restore product | Product belongs to merchant AND no orders in 'pending' status |

## 4. Business Rules

### 4.1 Product Creation Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-001 | Required Fields | Product must have: name, categoryId, price, description. | Backend (DTO validation) + Frontend (Zod schema) |
| BR-PROD-002 | Price Positive | Price must be greater than 0. | Backend (DB constraint `chk_products_price`) |
| BR-PROD-003 | Compare Price | compareAtPrice must be greater than price (if provided). | Backend (DTO validation) |
| BR-PROD-004 | SKU Uniqueness | SKU must be unique across all products (if provided). | Backend (DB constraint `uq_products_sku`) |
| BR-PROD-005 | Slug Generation | Slug auto-generated from product name, must be unique. | Backend (slug util) |
| BR-PROD-006 | Category Existence | Category must exist and be valid. | Backend (DB FK constraint) |
| BR-PROD-007 | Default Status | New products default to `is_active = true`. | Backend (DB default) |
| BR-PROD-008 | Default Featured | New products default to `is_featured = false`. | Backend (DB default) |

### 4.2 Product Image Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-009 | Max Images | Maximum 10 images per product. | Backend (DTO validation) |
| BR-PROD-010 | File Size | Maximum 5MB per image. | Backend (file upload validation) |
| BR-PROD-011 | File Types | Allowed: JPG, PNG, WebP. | Backend (MIME type validation) |
| BR-PROD-012 | Primary Image | First image is the primary/cover image. | Frontend (display logic) |
| BR-PROD-013 | File Naming | UUID-based filenames to prevent conflicts. | Backend (upload service) |

### 4.3 Product Status Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-014 | Active Visibility | Only `is_active = true` products are publicly visible. | Backend (query filter) |
| BR-PROD-015 | Inactive Hidden | Inactive products hidden from public view but visible to merchant. | Backend (role-based query) |
| BR-PROD-016 | Soft Delete | Delete sets `is_active = false`, does not remove record. | Backend (service logic) |
| BR-PROD-017 | Featured Flag | Featured products appear on home page. | Backend (query filter) |

### 4.4 Inventory Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-018 | Stock Non-Negative | Stock quantity cannot go below 0. | Backend (DB constraint `chk_products_stock`) |
| BR-PROD-019 | Low Stock Threshold | Default threshold is 10 units. Warning when stock ≤ threshold. | Backend (service logic) |
| BR-PROD-020 | Out of Stock | Products with 0 stock are marked as out of stock. | Backend (status logic) |
| BR-PROD-021 | Atomic Decrement | Stock decremented atomically on order creation. | Backend (DB transaction) |

### 4.5 Ownership Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-022 | Merchant Ownership | Merchants can only edit/delete their own products. | Backend (service check) |
| BR-PROD-023 | Admin Override | Admins can manage all products. | Backend (RBAC) |

### 4.6 Product Deletion Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-024 | Active Order Deletion Guard | Product cannot be soft-deleted if it has any associated orders with status NOT IN ('done'). Only products with no orders or all orders in 'done' status can be deleted. | Backend (service logic) |
| BR-PROD-025 | Deletion Restriction Message | When deletion is blocked due to active orders, display message: "Cannot delete product with active orders. All orders must be completed first." | Backend (error response) |

### 4.7 Pending Order CRUD Restriction Rules

| Rule ID | Rule Name | Description | Enforcement Layer |
|---------|-----------|-------------|-------------------|
| BR-PROD-026 | Pending Status Full CRUD Restriction | When a product has any associated order with status 'pending', ALL CRUD operations (Create, Read/Edit, Update, and Delete) are restricted for that product. Merchants cannot modify, update, or soft-delete products while the associated order status is 'pending'. This restriction supersedes all other CRUD permissions. | Backend (service logic) + Frontend (UI state) |
| BR-PROD-027 | Pending Status Redirect | When any process or operation is triggered/processed while an order is in 'pending' status, the system must automatically redirect the merchant/user to the Home Page ("/") instead of keeping them on the Product List or Product Detail page. | Frontend (router guard) + Backend (error response with redirect) |
| BR-PROD-028 | Post-Pending Restriction Removal | Once the order status reaches 'done', all CRUD restrictions imposed by BR-PROD-026 are removed, and normal CRUD and deletion operations are allowed for that product again. | Backend (service logic) |

## 6. Functional Operation Specification

### 6.1 Operation: Create Product (Merchant)

| Attribute | Specification |
|-----------|---------------|
| **Trigger** | Submit product form on `/merchant/products/new` |
| **API Endpoint** | `POST /api/v1/products` |
| **Request Content-Type** | `multipart/form-data` (for images) or `application/json` |
| **Pre-Submission Validation** | Full DTO validation (class-validator) |
| **Processing Steps** | 1. Validate JWT token and merchant role. 2. Verify merchant has approved shop. 3. Validate all required fields. 4. Generate slug from product name. 5. Check slug uniqueness. 6. Upload images (if provided). 7. Create product record in DB. 8. Invalidate product list cache. 9. Return created product DTO. |
| **Success Response** | 201 Created with product data |
| **Post-Action** | Redirect to merchant product list |
| **Pending Order Check** | N/A (new product, no existing orders) |

### 6.2 Operation: Update Product (Merchant)

| Attribute | Specification |
|-----------|---------------|
| **Trigger** | Submit product form on `/merchant/products/:id/edit` |
| **API Endpoint** | `PATCH /api/v1/products/:id` |
| **Request Content-Type** | `multipart/form-data` or `application/json` |
| **Pre-Submission Validation** | Full DTO validation, product ownership check |
| **Processing Steps** | 1. Validate JWT token and merchant role. 2. Verify product belongs to merchant. 3. **Check for pending orders: Query `order_items` for this product where linked order status = 'pending'.** 4. **If pending orders exist, return 409 Conflict with error and redirect to Home Page ("/") (BR-PROD-026, BR-PROD-027).** 5. Validate all fields. 6. Update product record. 7. Handle image additions/removals. 8. Invalidate product cache and list cache. 9. Return updated product DTO. |
| **Success Response** | 200 OK with updated product data |
| **Error Response (Pending Orders)** | 409 Conflict — "Cannot modify product with pending orders" + redirect to "/" |
| **Post-Action** | Stay on edit page or redirect to list |

### 6.3 Operation: Delete Product (Soft Delete) (Merchant)

| Attribute | Specification |
|-----------|---------------|
| **Trigger** | Click delete button on merchant product list |
| **API Endpoint** | `DELETE /api/v1/products/:id` |
| **Request Content-Type** | None |
| **Pre-Submission Validation** | Product ownership check |
| **Processing Steps** | 1. Validate JWT token and merchant role. 2. Verify product belongs to merchant. 3. **Check for pending orders: Query `order_items` for this product where linked order status = 'pending'.** 4. **If pending orders exist, return 409 Conflict with error and redirect to Home Page ("/") (BR-PROD-026, BR-PROD-027).** 5. Check for active orders: Query `order_items` for this product where linked order status NOT IN ('done'). 6. If active orders exist, return 409 Conflict with error message. 7. | **Success Response** | 204 No Content |
| **Error Response (Pending Orders)** | 409 Conflict — "Cannot delete product with pending orders" + redirect to "/" |
| **Error Response (Active Orders)** | 409 Conflict — "Cannot delete product with active orders. All orders must be completed first." |
| **Post-Action** | Remove product from list view, show success toast |

|------|:---------------:|:-------------:|:---------------:|:------------:|
| `merchant` | ✓ (own shop) | ✓ (own products) | ✓ (own products) | ✓ (own products) |

### 10.4 Ownership Enforcement

```typescript
// Backend ownership check example
const product = await this.prisma.product.findUnique({ where: { id } });
if (!product) throw new NotFoundException('Product not found');
if (user.role === 'merchant' && product.merchantId !== user.id) {
  throw new ForbiddenException('You can only manage your own products');
}

// Pending order check (applies to ALL CRUD operations — BR-PROD-026)
const pendingOrders = await this.prisma.orderItem.findFirst({
  where: {
    productId: id,
    order: {
      status: 'pending'
    }
  }
});
if (pendingOrders) {
  throw new ConflictException('Cannot modify product with pending orders');
}

// Active order check for deletion
const activeOrders = await this.prisma.orderItem.findFirst({
  where: {
    productId: id,
    order: {
      status: { notIn: ['done'] }
    }
  }
});
if (activeOrders) {
  throw new ConflictException('Cannot delete product with active orders');
}
```
