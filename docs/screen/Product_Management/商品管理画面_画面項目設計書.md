## 2. Screen Overview & Purpose (画面概要・目的)

### 2.1 Purpose (目的)
The Product Management screens enable merchants to manage their product catalog through full CRUD operations. Merchants can create, edit, delete products, manage inventory, upload product images, and toggle product visibility/status. Admin users have full access to all products.

### 2.2 Target Users & Roles (対象ユーザーと権限)

| Attribute | Value |
| :--- | :--- |
| **Primary Actors** | Authenticated merchant (own products), Admin (all products) |
| **Required Authentication** | JWT Bearer Token |
| **Data Scope** | Merchant: own products only. Admin: all products. |
| **Access Control** | Protected routes — JwtAuthGuard + RolesGuard (merchant/admin) |

### 2.3 Core Functions & Basic Design Principles (主要機能・基本設計方針)
1. **Product Listing** — View and manage merchant's product catalog with search/filter.
2. **Product Creation** — Create new product listings with full details and images.
3. **Product Editing** — Update existing product details, pricing, and metadata.
4. **Product Deletion** — Soft-delete products (set `is_active = false`).
5. **Image Management** — Upload, reorder, and remove product images (max 10, 5MB each).
6. **Inventory Management** — View and update stock quantities, low stock warnings.
7. **Status Toggle** — Toggle product active/inactive and featured status.
8. **Internationalization** — Full i18n support for EN, JA, MY.
9. **Responsive Design** — Mobile-first adaptive layout.

## 5. Item Behaviors & Event Specifications (各項目における挙動・イベント仕様)

### 5.1 Search Products (`txtSearch` onChange)
- **Trigger:** User types in search input (debounced 300ms).
- **Processing Logic:**
  1. **Client-Side Pre-Check:** Validate input length ≤ 100.
  2. **Backend Dispatch:** `GET /api/v1/products?search={query}&status={status}`.
  3. **Backend Execution:** Filter products by name/SKU containing query string.
  4. **Post-Execution UI:** Update product table with filtered results. Reset pagination to page 1.
- **Exception Handling:**
  - Network error: Display "Search failed. Please try again" in toast.

### 5.2 Filter by Status (`selStatusFilter` onChange)
- **Trigger:** User selects status filter option.
- **Processing Logic:**
  1. **Backend Dispatch:** `GET /api/v1/products?status={status}`.
  2. **Backend Execution:** Filter products by `is_active` status.
  3. **Post-Execution UI:** Update product table with filtered results. Reset pagination to page 1.
- **Exception Handling:** None applicable.

### 5.3 Add New Product (`btnAddProduct` onClick)
- **Trigger:** User clicks "Add New Product" button.
- **Processing Logic:**
  1. Navigate to `/merchant/products/new`.
  2. Initialize empty product form with default values.
- **Exception Handling:** None applicable.

### 5.4 Edit Product (`btnEdit` onClick)
- **Trigger:** User clicks edit button on product row.
- **Processing Logic:**
  1. Navigate to `/merchant/products/:id/edit`.
  2. Fetch product data from `GET /api/v1/products/:id`.
  3. Populate form fields with existing product data.
- **Exception Handling:**
  - `404`: Display "Product not found" and redirect to list.

### 5.5 Delete Product (`btnDelete` onClick)
- **Trigger:** User clicks delete button on product row.
- **Processing Logic:**
  1. **Confirmation Dialog:** Display "Are you sure you want to delete this product?" with Confirm/Cancel buttons.
  2. **On Confirm:** `DELETE /api/v1/products/:id`.
  3. **Backend Execution:** Set `is_active = false` (soft delete). Invalidate cache.
  4. **Post-Execution UI:** Remove product from list. Show success toast.
- **Exception Handling:**
  - `403`: Display "You don't have permission to delete this product".
  - `404`: Display "Product not found".

### 5.6 Toggle Active Status (`swtActive` onChange)
- **Trigger:** User toggles active switch on product row.
- **Processing Logic:**
  1. **Backend Dispatch:** `PATCH /api/v1/products/:id` with `{ isActive: newValue }`.
  2. **Backend Execution:** Update `is_active` boolean. Invalidate cache.
  3. **Post-Execution UI:** Update status badge. Show success toast.
- **Exception Handling:**
  - `403`: Display "Permission denied". Revert switch state.

### 5.7 Toggle Featured Status (`swtFeatured` onChange)
- **Trigger:** User toggles featured switch on product row.
- **Processing Logic:**
  1. **Backend Dispatch:** `PATCH /api/v1/products/:id` with `{ isFeatured: newValue }`.
  2. **Backend Execution:** Update `is_featured` boolean. Invalidate cache.
  3. **Post-Execution UI:** Show/hide featured badge. Show success toast.
- **Exception Handling:**
  - `403`: Display "Permission denied". Revert switch state.

### 5.8 Product Form Submit (`btnSave` onClick)
- **Trigger:** User clicks "Save Product" / "Update Product" button.
- **Processing Logic:**
  1. **Client-Side Pre-Check:** Full Zod schema validation — all required fields valid, price > 0, images uploaded.
  2. **Backend Dispatch:** `POST /api/v1/products` (Create) or `PATCH /api/v1/products/:id` (Update) with `multipart/form-data`.
  3. **Backend Execution:** Validate DTO. Generate slug. Upload images. Create/update product record. Invalidate cache.
  4. **Post-Execution UI:** Show success toast. Navigate to `/merchant/products`.
- **Exception Handling:**
  - `VAL_001` (400): Display field-specific validation errors inline.
  - `409`: Display "A product with this name/SKU already exists" on relevant field.
  - `413`: Display "Image file must not exceed 5MB".
  - `415`: Display "Only JPG, PNG, and WebP images are supported".
  - Network error: Display "Network error. Please check your connection".

  3. **Backend Execution:** Set `is_active = false` (soft delete) for all selected products. Invalidate product list cache.
  4. **Post-Execution UI:** Remove affected products from list (or update status to inactive). Clear selection. Show success toast: "{N} products deleted". Close dialog.

- **Processing Logic:**
  1. **Detection:** Backend checks `stockQuantity ≤ lowStockThreshold` after stock mutation.
  2. **UI Update:** Display warning badge on product row: amber background with text "Low Stock ({N} remaining)".
  3. **Product List:** Highlight entire row with `bg-amber-50` when low stock.
- **Exception Handling:** None applicable.

### 5.23 Out of Stock Notification (Real-Time)
- **Trigger:** Product stock quantity reaches 0 after any stock update or order creation.
- **Processing Logic:**
  1. **Detection:** Backend detects `stockQuantity = 0`.
  2. **UI Update:** Display "Out of Stock" badge on product row: red background with text "Out of Stock".
  3. **Product List:** Highlight entire row with `bg-red-50` when out of stock.
  4. **Cart Behavior:** Product cannot be added to cart when out of stock (enforced backend).
- **Exception Handling:** None applicable.

### 5.24 Delete All Products (`btnDeleteAll` onClick → `dlgDeleteAllConfirm` → `dlgDeleteAllConfirmBtn` onClick)
- **Trigger:** User clicks "Delete All" button in Action Bar.
- **Processing Logic:**
  1. **Pre-Check:** Fetch total count of products matching current filters (search query, status filter) from API or cached `meta.total`.
  2. **Confirmation Dialog:** Open `dlgDeleteAllConfirm` with description: "Are you sure you want to delete all {count} products? Products with active orders will be skipped. This action cannot be undone."
  3. **On Confirm:** `DELETE /api/v1/products/all` with body `{ search?: string, isActive?: boolean }` reflecting current filter state.
  4. **Backend Execution (BR-PROD-024):**
     - Build Prisma where clause from filters + `merchantId = userId`.
     - Query all matching product IDs.
     - For each product, check active orders: query `order_items` where linked order `status NOT IN ('delivered', 'cancelled')`.
     - Products **without** active orders: set `isActive = false` (soft delete).
     - Products **with** active orders: skip, add to `skipped` array.
     - Log `BULK_DELETE_ALL` audit event.
     - Invalidate `cache:products:list:*`.
  5. **Post-Execution UI:**
     - If all deleted (`skipped === 0`): Show success toast: "Successfully deleted {deleted} products."
     - If partial (`skipped > 0`): Show warning toast: "Successfully deleted {deleted} products. {skipped} products could not be deleted because they have active orders."
     - Close dialog. Refresh product list.
- **Exception Handling:**
  - `403`: Display "You don't have permission to delete some products". Show partial success if applicable.
  - Network error: Display "Delete all failed. Please try again". Close dialog.

## 11. Special UI Notes & Styling Constraints (特記事項・UI仕様)

- **Design System:** Luxury Cosmetics Theme — Primary `#7C3AED` (Purple), Accent `#EC4899` (Pink), Secondary `#F3E8FF` (Lavender).
- **Responsive Viewport Design:** Full-width form on all breakpoints. Table scrolls horizontally on mobile.
- **Accessibility:** Every control must be keyboard navigable. ARIA labels required. Error messages must be announced via `role="alert"`.
- **Performance:** Product list uses skeleton loaders during initial load. Image upload shows progress bar. Buttons display spinner during async operations.
- **Security:** All user input is sanitized to prevent XSS. File uploads validated server-side (MIME type + magic bytes). Never trust client-side validation alone.
- **Design Tokens:** Status badges use standard color mapping — success: `bg-green-100 text-green-800`, error: `bg-red-100 text-red-800`, warning: `bg-amber-100 text-amber-800`, featured: `bg-yellow-100 text-yellow-800`.
