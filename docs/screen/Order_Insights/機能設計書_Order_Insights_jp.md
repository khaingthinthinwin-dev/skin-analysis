# 機能設計書 - Order Insights

> 文書ID: SKM-FDS-OI-001 | バージョン: 3.0 | 状態: 現行ソース整合版 | 最終更新: 2026-10-15

## 1. 目的と対象範囲

本書は、現在実装されている購入者の注文一覧・詳細、販売者のOrder Insights・注文詳細、管理者の注文一覧・詳細を定義します。`frontend/src/app/routes.tsx`、`frontend/src/pages/order-insights/` の画面、および対応するバックエンドのController/Serviceを基準とします。未実装要件を現行機能として記述せず、実装上の既知課題も明記します。

Insightsの一覧・サマリー画面は参照中心です。一方、隣接する注文APIには注文作成（`POST /api/v1/orders`）と販売者のステータス更新（`PATCH /api/v1/merchant/orders/:id/status`）があります。ステータス更新はOrder Fulfillmentの責務で、販売者の注文詳細画面から実行できます。一覧画面からステータスは更新しません。

## 2. ロールと画面URL

| ロール | URL | 機能 |
|---|---|---|
| 購入者 | `/orders` | 自分の注文一覧、絞り込み、KPI、CSV出力 |
| 購入者 | `/orders/:id` | 自分の注文詳細と配送状況。独立した追跡画面は登録されていません |
| 販売者 | `/merchant/order-insights` | 自店舗の注文一覧、販売件数、売上サマリー、絞り込み、CSV出力 |
| 販売者 | `/merchant/orders/:id` | 自店舗の注文詳細、顧客情報、配送履歴、請求書、利用可能なステータス更新 |
| 管理者 / super_admin | `/admin/orders` | 全注文一覧、絞り込み、KPI、CSV出力 |
| 管理者 / super_admin | `/admin/orders/:id` | 注文詳細、顧客・店舗情報、配送状況、印刷/PDF保存 |

## 3. 機能仕様

### 3.1 購入者の注文一覧

- `GET /api/v1/orders` から取得します。所有者の絞り込みはサーバー側で行います。
- ステータス、店舗名検索、注文番号検索、期間、並び替え、ページネーション、CSV出力に対応します。
- テーブル項目は注文番号、日付、店舗、商品数、合計、支払状況、注文状況、Track操作です。Track操作は `/orders/:id`（注文詳細）を開き、独立した追跡URLには遷移しません。
- ページサイズは10、20、50、100件。初期値は10件です。
- 日付条件なしでステータスがAll/placed/deliveredの場合、KPIに固定のサンプル値を表示します。それ以外の条件ではAPIのsummaryを使います。固定値は実集計ではなく既知の実装課題です。
- CSV出力は一致する全ページを取得し、各注文の詳細を読み込んでブラウザー上で生成します。出力中または対象注文が0件の場合は無効です。

### 3.2 購入者の注文詳細

- `GET /api/v1/orders/:orderId` から取得します。所有権がない場合はNot Foundとして扱います。
- 注文番号/日付/状況、保存済み価格の商品、割引・クーポン（存在する場合）、合計、支払方法/状況、配送先、メモ（存在する場合）、注文履歴に基づく配送状況を表示します。
- 注文一覧へ戻る操作と、請求書の印刷/ダウンロードを提供します。顧客情報カードは表示しません。

### 3.3 販売者のOrder Insights一覧

- APIが返す本日、今月、配達完了の注文件数を表示します。
- 売上サマリーはToday、This Month、Last Month、Customに対応します。Customでは開始日・終了日を必須とし、未来日を禁止、開始日 <= 終了日を検証します。
- Sales、Commission、Revenue（手数料控除後）、AOV、注文数、手数料率の説明をまとめて表示します。画面の金額はKs単位に丸めます。バックエンドは期間内の全注文に現在の手数料設定/既定値を適用し、注文ごとの保存済み手数料率では集計しません。
- 注文一覧はステータス、支払状況、期間、注文番号検索、並べ替え、URL連動フィルター、ページネーション、Resetに対応します。
- Completed Ordersタイルを選ぶと`status=delivered`を適用し、1ページ目に戻って一覧までスクロールします。
- Exportダイアログから、条件に一致する全ページを取得してCSVを生成します。
- 画面のいずれかのクエリが403の場合はアクセス拒否アラートを表示します。それ以外の取得エラーには領域ごとの再試行を表示し、0件は情報用の空状態で示します。

### 3.4 販売者の注文詳細・フルフィルメント

- `/api/v1/merchant/orders/:id` と`/:id/tracking`から、自店舗の詳細と履歴を取得します。
- 注文番号、現在状況、配送進捗/履歴、商品、注文時の手数料率と計算情報、合計、顧客名/メール/電話、配送先、支払情報、メモ（存在する場合）を表示します。
- 注文番号コピー、請求書ダイアログ、一覧へ戻る操作を提供します。バックエンドが次の遷移先を返す場合のみステータス更新操作を表示し、確認後にPATCHします。処理中とエラーを画面に表示します。
- 他店舗の注文や存在しない注文はNot Foundとして扱います。ステータス更新はOrder Fulfillmentの書き込み操作です。

### 3.5 管理者の注文一覧・詳細

- 管理者一覧は初期状態で全注文を対象とし、ステータス、支払状況、期間、店舗/販売者検索、注文番号検索、並べ替え、ページネーション、フィルターチップ、Reset、CSV出力に対応します。
- 一致件数、集計KPI、購入者/店舗列、条件に応じた空状態を表示します。
- 詳細画面は商品、合計、支払、顧客・店舗/販売者情報、配送先、メモ、配送状況を表示し、注文番号コピー、印刷/PDF保存、一覧へ戻る操作を提供します。ステータス更新操作はありません。

## 4. データ範囲とアクセス制御

- 注文APIとサマリーAPIは認証が必要です。
- 購入者は自分の注文のみを参照します。販売者はJWTから販売者を解決し、承認済みライセンスを必要とします。管理者/super_adminは全注文を参照でき、店舗/販売者で絞り込めます。
- 購入者/販売者による管理者専用のmerchantId/shopId指定はバックエンドで拒否します。
- 詳細データが存在しない場合とアクセス範囲外の場合は404で秘匿します。
- 顧客情報は販売者/管理者の詳細投影にのみ含まれ、購入者画面には顧客情報カードを表示しません。

## 5. API・入力検証

| 操作 | API |
|---|---|
| 注文一覧 | `GET /api/v1/orders` |
| 購入者/管理者共通の詳細 | `GET /api/v1/orders/:orderId` |
| 注文追跡データ | `GET /api/v1/orders/:orderId/tracking` |
| 販売者詳細/履歴 | `GET /api/v1/merchant/orders/:id`, `GET /api/v1/merchant/orders/:id/tracking` |
| 販売者の状態更新 | `PATCH /api/v1/merchant/orders/:id/status` |
| 販売件数サマリー | `GET /api/v1/order-insights/merchant/sales-summary` |
| 売上サマリー | `GET /api/v1/order-insights/merchant/revenue-summary` |

一覧条件は6種類のステータス、page >= 1、limit 1～100、sort（createdAt/totalAmount/status）、asc/desc、任意の日付、支払状況（pending/completed）、最大100文字の検索文字列を検証します。Custom期間は両日付必須で、開始日が終了日を超えてはいけません。サマリーAPIはエンドポイントごとにユーザーあたり毎分30回に制限されます。確認した注文一覧/詳細Serviceに別個の毎分60回制限はありません。

## 6. 既知課題・対象外

1. 購入者KPIの一部は固定サンプル値です。本番の集計値として扱う前にサーバー集計へ置き換える必要があります。
2. 購入者の追跡情報は注文詳細内に表示されます。独立した追跡画面URLは未登録です。
3. 売上サマリーは現在の手数料設定/既定値を使い、注文ごとの保存済み率を用いません。
4. CSVはブラウザー側で生成します。サーバーCSV APIはありません。
5. E2EにはTODOが残っており、テストシナリオの記述だけでは動作検証済みとはいえません。
6. サマリーキャッシュ無効化は現在の注文作成/フルフィルメント処理から呼び出されず、管理者の全店舗キャッシュも店舗単位の無効化では消去されません。
