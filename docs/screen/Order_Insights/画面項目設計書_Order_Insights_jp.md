# 画面項目設計書 - Order Insights

> 文書ID: SKM-SSD-OI-001 | バージョン: 3.0 | 状態: 現行ソース整合版 | 最終更新: 2026-10-15

## 1. 対象と共通表示

本書は`frontend/src/app/routes.tsx`に登録された画面を対象にします。購入者の配送状況は注文詳細内に表示され、独立した追跡画面URLはありません。販売者一覧のURLは`/merchant/order-insights`です。項目・動作は現在の画面/コンポーネントを基準とし、既知の仮データは明記します。

ラベルはi18nextと英語フォールバックを使用します。注文状況・支払状況のバッジは表示専用です（販売者詳細のステータス更新操作を除く）。金額はコンポーネントに`formatCurrencyAmount`を使う一覧ではKs単位に丸めます。購入者詳細は現在USD・小数2桁で表示します。レスポンシブ表示は実装済みTailwindクラスと各テーブル/進捗コンポーネントの横スクロールに従います。

## 2. 購入者 注文一覧 - `/orders`

対象: `BuyerOrdersPage.tsx`、`OrderFilterBar.tsx`、`OrderHistoryTable.tsx`、`OrderPagination.tsx`。

| 項目 | 種別/データ | 初期値・必須 | 動作 |
|---|---|---|---|
| ページタイトル | 見出し | My Orders | ローカライズ表示。 |
| KPI | 4つの統計カード | データ取得後 | 注文数、合計支出、処理中、配達済み。日付条件なしのall/placed/deliveredでは固定サンプル値を表示。既知の仮実装。その他はAPI summaryを使用。 |
| ステータス | セレクト | all | 6ステータス/all。変更時に1ページ目へ戻る。 |
| 店舗検索 | テキスト入力 | 空 | 入力を遅延反映。店舗名/販売者名を検索。 |
| 注文番号検索 | テキスト入力 | 空 | 入力を遅延反映。表示用UUID先頭8文字を検索。 |
| From / To | 日付入力 | 空 | 注文日範囲。逆転した範囲は検証で拒否。 |
| Apply / Reset | ボタン | 条件による | 適用/初期化し、ページを1に戻す。 |
| Export | ボタン/ダイアログ | 出力中または0件なら無効 | 現在条件のCSVをブラウザーで生成。 |
| 注文テーブル | テーブル | APIデータ | 注文番号、日付、店舗、商品数、合計、支払、注文状況、Track。日付/合計で並べ替え。購入者画面のステータス列は並べ替え不可。 |

| ページネーション | 操作部 | 1ページ目、10件 | 10/20/50/100件。ページ/件数をURL状態に反映。 |

購入者CSV項目は注文番号、日付、商品名・数量、合計、支払状況、注文状況です。対象全件のページと各注文詳細を取得してから生成します。

## 8. 共通検証と状態

- 一覧フィルターはURLと連動します。フィルター/検索/ソート変更はページを1へ戻し、ページサイズ変更も同様です。
- スキーマは6ステータス、支払状況all/pending/completed、検索最大100文字、page >= 1、limit 1～100、sort createdAt/totalAmount/status、order asc/descを定義します。
- RevenueのCustom期間は両日付必須、開始日 <= 終了日。日付ダイアログは未来日を許可しません。
- ロール範囲、所有権、サーバー検証、レスポンス値はバックエンドが決定します。
- ロールごとに一覧行/詳細項目が異なります。購入者の詳細に顧客PIIを表示しません。

## 9. 既知の実装課題

- 購入者KPIの一部は固定サンプル値です。
- 購入者の独立した追跡画面はなく、注文詳細内に進捗を表示します。
- Revenue Summaryは現在の手数料設定/既定値を使い、注文別保存率を集計しません。
- CSVはクライアント生成で、サーバー出力APIはありません。
- E2EにはTODOがあり、すべての項目がE2E検証済みではありません。
