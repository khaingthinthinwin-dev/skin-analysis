## 1. 機能概要

### 1.1 目的と範囲

本画面群は、プラットフォーム管理者に対して、手数料設定の管理、収益パフォーマンスの監視、出品者別の手数料レポートの確認、および出品者への支払い（ペイアウト）処理を行うために必要なツールを提供します。

手数料・収益管理サブシステムは、財務の透明性を確保し、プラットフォーム手数料、ペイアウト、および収益トレンドに対する管理上の統制を可能にします。

### 1.2 機能責任

本画面群は以下のコア機能領域を担当します：

1. **手数料率設定** — 管理者が新規取引に適用されるプラットフォーム手数料率を設定・永続化できるようにします。
2. **手数料レポート生成** — フィルタリング、ソート、ページネーションを備えた出品者別手数料レポートを生成します。
3. **収益ダッシュボードKPI** — 設定可能な期間範囲にわたる収益KPIとトレンド可視化を表示します。
4. **広告料金収益の追跡** — ダッシュボードでコミッション収益とともに広告料金収益を追跡・表示します。
5. **支払いステータス内訳** — 完了、保留中、返金されたレコード（注文支払い：pending/completed、広告支払い：pending/completed/refunded）にわたる支払いステータスを集計します。
6. **出品者ペイアウト管理** — 冪等性とステータス追跡を備えた出品者ペイアウトを処理します（コミッション控除のみ。広告料金はプラットフォーム収益であり、ペイアウトから控除されることはありません）。
7. **収益目標進捗** — 月次/四半期の収益目標を設定し、ゲージバーによる現在の進捗を表示します（完了済み/確定済みの注文売上のみ。広告料金は除外）。 
8. **AI収益予測** — 過去データから収益とプラットフォーム手数料を予測し、現在のトレンドに沿った点線として描画します。
9. **監査とエラー処理** — 財務アクションを記録し、一貫したエラー状態を表示します。
10. **国際化とレスポンシブUI** — EN / JA / MYの対応とレスポンシブレイアウトをサポートします。

## 3. 状態遷移仕様

### 3.1 手数料ページの状態

| 状態 | 説明 | 手数料率を編集可能 | レポートを表示可能 |
|-------|-------------|:-------------:|:----------------:|
| `INITIAL` | ページがデータを読み込み中 | ✓ | ✓ |
| `READY` | データ描画済み | ✓ | ✓ |
| `ERROR` | 読み込み失敗 | ✗ | ✗ |

### 3.2 収益ページの状態

| 状態 | 説明 | KPIを表示可能 | 目標を表示可能 | 予測を表示可能 | ペイアウトを処理可能 |
|-------|-------------|:-------------:|:---------------:|:-----------------:|:------------------:|
| `INITIAL` | ページがデータを読み込み中 | ✓ | ✓ | ✓ | ✗ |
| `READY` | データ描画済み | ✓ | ✓ | ✓ | ✓ |
| `ERROR` | 読み込み失敗 | ✗ | ✗ | ✗ | ✗ |

### 3.3 目標の状態遷移

| 遷移ID | 起点 | 目標 | トリガー | ガード |
|---------------|--------|--------|---------|-------|
| TR-COMM-04 | none | active | 目標が保存される | 金額 > 0、有効な期間 |
| TR-COMM-05 | active | active | 目標が更新される | 新しい金額 > 0、有効な期間 |
| TR-COMM-06 | active | none | 目標がクリアされる | 管理者が目標を削除 |

### 3.3 ペイアウトの状態遷移

| 遷移ID | 起点 | 目標 | トリガー | ガード |
|---------------|--------|--------|---------|-------|
| TR-COMM-01 | pending | processing | ペイアウト処理がクリックされる | ペイアウトが存在し、ステータス = pending |
| TR-COMM-02 | processing | completed | バックエンドが支払いを確認 | 成功レスポンス |
| TR-COMM-03 | pending | failed | バックエンドが処理を拒否 | バリデーション失敗 |

## 4. ビジネスルール

### 4.1 手数料率ルール

| ルールID | ルール名 | 説明 | 適用レイヤー |
|---------|-----------|-------------|-------------------|
| BR-COMM-001 | 手数料率の範囲 | プラットフォーム手数料率は0より大きく100以下の範囲の小数で、小数第2位までに制限される（DBチェック：`commission_rate > 0 AND commission_rate <= 100`）。デフォルトは12%。 | バックエンド（DTOバリデーション + DBチェック制約）+ フロントエンド（フォームバリデーション） |
| BR-COMM-002 | 手数料率の永続化 | 手数料率は保存された時点からすべての新規取引に適用され、過去の請求書には影響しない。 | バックエンド（サービスロジック） |

### 7.7 出力定義 — 収益目標・予測（出力定義）

| フィールド | データソース | 表示形式 |
|-------|-------------|----------------|
| `target` | 収益目標レコード + 集計 | `{ targetAmount, period, actualRevenue, progressPercent }` のオブジェクト |

## 9. エラー処理仕様

### 9.1 エラーレスポンス構造

```json
{
  "statusCode": 400,
  "message": ["commissionRate must be a number greater than 0 and at most 100"],
  "error": "Bad Request",
  "timestamp": "2026-08-06T12:00:00.000Z",
  "path": "/api/v1/admin/commission"
}
```

### 9.2 エラー分類テーブル — 手数料

| HTTPステータス | エラーコード | シナリオ | ユーザー向け動作 |
|-------------|------------|----------|---------------------|
| `400` | `COMM_001` | 無効な手数料率 | 編集ダイアログにインラインフィールドエラーを表示 |
| `403` | `COMM_002` | 管理ルートへの不正アクセス | `/unauthorized` へのリダイレクトまたはアラート表示 |

### 9.3 エラー分類テーブル — 収益 / ペイアウト / 広告料金

| HTTPステータス | エラーコード | シナリオ | ユーザー向け動作 |
|-------------|------------|----------|---------------------|
| `400` | `COMM_005` | 無効な目標金額または期間 | 目標編集ダイアログにインラインフィールドエラーを表示 |
| `404` | `COMM_003` | ペイアウトが見つからない | アラートバナー + 一覧の更新 |
| `409` | `COMM_004` | ペイアウトが処理済み | アラートバナー + アクションの無効化 |
| `422` | `COMM_006` | 予測用の過去データが不十分 | 情報ノート表示、予測の点線を非表示 |
| `404` | `ADFE_001` | 広告料金レコードが見つからない | アラートバナー + 広告料金データの更新 |
| `500` | `SYS_001` | サーバーエラー | 再試行オプション付きアラートバナー |
| network | `NET_ERR` | ネットワーク障害 | 接続問題のアラートバナー |

### 9.4 エラー分類テーブル — エクスポート

| HTTPステータス | エラーコード | シナリオ | ユーザー向け動作 |
|-------------|------------|----------|---------------------|
| `400` | `EXP_001` | dateFromまたはdateToが未指定 | 「開始日と終了日は必須です」 |
| `400` | `EXP_002` | dateToがdateFromより前 | 「終了日は開始日以降である必要があります」 |
| `400` | `EXP_003` | 日付範囲が365日を超える | 「日付範囲は365日を超えることはできません」 |
| `400` | `EXP_004` | 無効な形式 | 「無効なエクスポート形式です。CSVまたはExcelを使用してください」 |
| `404` | `EXP_005` | エクスポートジョブが見つからない | 「エクスポートジョブが見つかりません」 |
| `410` | `EXP_006` | エクスポートファイルの有効期限切れ | 「このエクスポートの有効期限が切れています。新しいものを生成してください」 |
| `500` | `EXP_007` | エクスポート生成失敗 | 「レポートの生成に失敗しました。もう一度お試しください」 |

### 9.5 フロントエンドのエラー表示動作

- **フィールドレベルバリデーション**: 無効な入力の下に赤い枠線とインラインテキストを表示。
- **フォームレベルサマリー**: すべてのエラーを一覧表示するフォーム上部のアラートバナー。
- **トースト通知**: APIエラーと成功アクション（手数料率の更新、ペイアウト処理）に使用。
- **読み込み状態**: API呼び出し中のスケルトン読み込みとボタン上のスピナー。

### 15.4 監査 / 検証チェックリスト

- [ ] 手数料率の更新、目標の更新、ペイアウト処理について監査ログエントリが作成される
- [ ] 通貨の値が浮動小数点数として描画されない（文字列安全なフォーマット）
- [ ] 目標進捗計算が返金を除外する（KPIの範囲と整合）
- [ ] 予測値が財務記録に書き戻されたり、集計に使用されたりしない
- [ ] 広告料金収益がプラットフォーム合計収入KPIに含まれる
- [ ] 広告料金支払いステータスが注文支払いステータスとともに追跡される
- [ ] 支払いステータスパネルは、サポート対象のステータスのみをバランスの取れたグリッド間隔で表示する（注文：完了/保留中、広告：完了/保留中/返金）
- [ ] 広告料金トレンド系列が収益チャートに個別ラインとして描画される
- [ ] 広告料金がペイアウト控除計算に含まれない
- [ ] 収益目標進捗は広告料金を除外し、注文売上（`order_items.total_price`）から集計される
- [ ] 手数料率は0より大きく100以下で、小数第2位まで入力できる（デフォルト12%）
