## 1. 機能概要

### 1.1 目的と範囲

この画面は、Cosmetics Finderプラットフォーム内におけるパーソナライズ商品発見のエントリーポイントとして機能する。マッチング＆おすすめサブシステムは、バイヤーがAI肌分析結果に基づいたパーソナライズされたスキンケア商品のおすすめを受け取るためのすべての機能を提供し、多次元マッチングフィルタ（肌タイプ、成分、価格帯）を通じてそれらのおすすめを絞り込み、商品詳細コンテキストから類似商品を発見する機能を提供する。

このサブシステムは、AI肌分析と商品カタログを橋渡しする。バイヤーのAI検出肌状態をランク付けされ、スコア付きの互換性のある商品セットに変換し、Redisキャッシュを通じてパフォーマンスを維持し、承認されたマーチャントショップから提供されるアクティブな商品のみが表示されることを保証する。

さらに、サブシステムはバイヤーの完了したAI肌分析結果からおすすめ履歴を取得し、再エンゲージメントを可能にし、承認されたマーチャントの広告をクロス画面スライドダウンパネルに透過開示とともに表示する。

### 1.2 機能責任

この画面は以下のコア機能領域を担当する：

1. **パーソナライズおすすめ** — バイヤーの肌タイプ、肌の悩み、最新のAI肌分析結果に基づいて、ランク付けされた商品リスト（「あなたへのおすすめ」）を計算する。
2. **マッチングスコア計算** — 肌タイプ互換性、肌の悩みマッチ、平均評価、注目状態に基づいて、各商品に0〜100のマッチスコアを付与する。
3. **類似商品発見** — 商品詳細ページの特定の商品と類似した商品（同じカテゴリと肌タイプ互換性）をおすすめする。
4. **多次元マッチングフィルタ** — 肌タイプ、成分、価格帯によるおすすめの絞り込みを可能にする。
5. **分析結果条件付き表示** — AI分析結果が利用可能な場合はそれを使用し、利用不可の場合は汎用的な注目・トップ評価のおすすめ結果とAI分析実行のプロンプトを表示する。
6. **肌タイプ互換性表示** — おすすめの互換肌タイプとマッチスコアを各カードに表示し、バイヤーに商品がおすすめされた理由を理解させる。
7. **キャッシュ** — Redisから繰り返しのパーソナライズおすすめクエリを提供し、パフォーマンスターゲットを達成し、分析変更時に無効化する。
8. **おすすめ履歴** — バイヤーの完了したAI肌分析結果から過去のおすすめを取得して再エンゲージメントを可能にする。
9. **広告表示** — クロス画面スライドダウンパネルでの承認認済みマーチャント広告のみを透過開示とともに表示する。支払金額とローテーション順で優先順位付け。
10. **クロス画面広告パネル** — リユーザブルなスライドダウンパネルコンポーネント（D0）。6画面（ホームページ、検索、カテゴリ、商品詳細、おすすめ、カート）でスポンサード広告を表示。画像、タイトル、説明文、CTAボタン、5秒自動スライドローテーション、ラウンドロビン広告配信。

### 1.3 対象ユーザー

| 属性 | 値 |
|-----------|-------|
| **プライマリアクター** | バイヤー（認証済み；分析結果がある場合はAI結果おすすめ、分析結果がない場合は汎用おすすめ結果） |
| **必要認証** | JWT Bearer Token（`/buyer/recommendations`ページ / おすすめAPI）、不要（商品詳細ページの類似商品） |
| **データスコープ** | 利用可能な場合は自身の最新AI分析結果。それ以外の場合はグローバルなアクティブ商品カタログ（汎用結果、フィルタ、類似商品用） |

## 3. 状態遷移仕様

### 3.1 おすすめページUI状態

| 状態 | 説明 | 表示される結果 | 利用可能なアクション |
|-------|-------------|:-----------------:|-------------------|
| `IDLE` | ページロード済み、クエリ実行中でない | ✓（デフォルトまたはキャッシュ済みリスト） | フィルタ、ソート、ページネーション |
| `LOADING` | クエリ実行中 | スケルトングリッド | 新しいクエリ（実行中のものを置換） |
| `SUCCESS` | クエリが正常に返却 | ✓ | ソート、フィルタ、ページネーション、詳細表示 |
| `EMPTY` | クエリがゼロ一致を返却 | 空状態 | フィルタリセット |
| `ERROR` | クエリ失敗（ネットワーク/5xx） | エラーバナー | リトライ |

### 3.3 おすすめソース選択

このページはバイヤー選択モードを公開も要求もしない。バックエンドはバイヤーの分析の有無からおすすめソースを選択する。

| ソース | 説明 | 使用条件 | UI指標 | リフレッシュ可能 |
|--------|-------------|-----------|---------------|:-----------:|

### 6.1 動作：パーソナライズおすすめ取得

| 属性 | 仕様 |
|-----------|---------------|
| **トリガー** | ページロード、フィルタ／ソート変更 |
| **APIエンドポイント** | `GET /api/v1/recommendations/personalized` |

## 9. エラー処理仕様

### 9.1 エラーレスポンス構造

```json
{
  "statusCode": 400,
  "message": ["limit must not be greater than 50"],
  "error": "Bad Request",
  "timestamp": "2026-08-13T12:00:00.000Z",
```

### 9.2 エラー分類表 — パーソナライズおすすめ

| HTTPステータス | エラーコード | シナリオ | ユーザー向け動作 |
|-------------|------------|----------|---------------------|
| `400` | `BAD_REQUEST` | バリデーション失敗（無効なパラメータ） | インラインバリデーションヒント＋トップバナー |
| `400` | `BAD_REQUEST` | 広告パネルの無効なコンテキストID | パネル非表示（サイレント） |
| `401` | `UNAUTHORIZED` | パーソナライズエンドポイントでトークン無し/無効 | ログインにリダイレクト |
| `403` | `FORBIDDEN` | 非buyerロールがパーソナライズアクセスを試行 | /unauthorizedにリダイレクト |
| `404` | `NOT_FOUND` | 類似商品が見つからない（無効なproductId） | 空状態／類似セクション非表示 |
| `404` | `NOT_FOUND` | 履歴レコードが見つからない（無効なhistoryId） | サイレント無視（トラッキングのユーザー向けエラーなし） |
| `429` | `TOO_MANY_REQUESTS` | パブリックな類似エンドポイントでレート制限超過 | 「リクエストが多すぎます。お待ちください」＋リトライカウントダウン |
| `429` | `TOO_MANY_REQUESTS` | 広告パネルエンドポイントでレート制限超過 | パネル非表示（サイレント、ユーザー向けエラーなし） |
| `500` | `INTERNAL_SERVER_ERROR` | サーバーエラー | 「問題が発生しました」＋リトライボタン |

### 9.3 フロントエンドエラー表示動作

- **フィールドレベルバリデーション**：無効なフィルタ入力の下に赤いボーダーとインラインテキスト（例：minPrice > maxPrice）。
- **フォームレベルサマリー**：結果エリア上部にすべてのエラーを一覧表示するアラートバナー。
- **ローディング状態**：フェッチ中のスケルトンシマーグリッド（shadcn `Skeleton`）。適用ボタン上のスピナー。
- **空結果**：メッセージ＋「フィルタリセット」ボタンの`EmptyState`コンポーネント。
- **リトライ**：一時的な障害に対するTanStack Query `error`＋`refetch`。

### 9.4 監査／ログ

| イベント | ログデータ | 保持期間 |
|-------|-------------|-----------|
| `RECOMMENDATION_EXECUTED`（500ms超のスロークエリにwarnレベル） | userId（ログイン時）、ソース、フィルタ、結果件数、所要時間 | 30日間 |
| `RECOMMENDATION_SOURCE_EMPTY`（info） | userId、理由（分析なし） | 30日間 |

ルール：
- レスポンスボディ全体はログに記録しない（セキュリティ）。
- 皮膚分析画像データや、イベントフィールドに既にある識別子以外の個人健康データはログに記録しない。
- NestJS `Logger`を`[MatchingService]`コンテキストで使用。`console.log`は使用しない。

## 10. 権限とアクセス制御

## 11. リアルタイム通知動作

### 11.1 現在の実装

マッチング＆おすすめ画面は標準的なREST APIコールで動作。この機能にはリアルタイムWebSocket接続は不要。パーソナライゼーションの変更（新しい分析）は次のクエリで反映（5分間のパーソナライズキャッシュTTLと分析変更時の即時キャッシュ無効化で軽減）。

### 11.2 クライアントサイド状態更新

| `matching:paramChange` | URLクエリパラメータ変更 | おすすめクエリの再フェッチ（TanStack Query無効化） |
| `matching:analysisCompleted` | 新しいAI分析結果返却 | ユーザーキャッシュキーを無効化し、`source = ai`で再フェッチ |
| `matching:filterApplied` | フィルタ適用／フィルタリセット | `page`を1にリセットし再フェッチ |
| `matching:pageChange` | ページネーションコントロールクリック | `page`を更新し`keepPreviousData`で再フェッチ |
| `matching:adClicked` | バイヤーがパネルのCTAをクリック | サイレントForget `POST /ads/track/click`、商品にナビゲート |
| `ad:panelLoaded` | 広告パネルが可視化（IntersectionObserver ≥ 50%） | サイレントForget `POST /ads/track/impression`（可視化ad IDs） |
| `ad:panelSlideChanged` | 自動スライドまたは手動ナビゲーション | ドットインジケーター更新、ホバー／タッチで自動スライド一時停止 |
| `ad:panelCtaClicked` | バイヤーが広告スライドのCTAボタンをクリック | サイレントForget `POST /ads/track/click`、`ad.linkUrl`にナビゲート |

## 13. 非機能要件

### 13.1 パフォーマンス要件（開発ルールセクション10.1、10.2、10.3）

| 指標 | ターゲット |
|--------|--------|
| パーソナライズおすすめレスポンスタイム（10Kレコード） | ≤ 3秒（NFR-002） |
| APIレスポンスタイム（p95） | ≤ 500ms（NFR-003） |
| フィルタ適用時間 | ≤ 500ms |
| マッチスコア計算（インメモリ） | ≤ 50ms |
| キャッシュヒットレスポンスタイム | ≤ 200ms |
| 類似商品レスポンスタイム | ≤ 500ms |
| ページロード（初期描画） | ≤ 2秒（NFR-001） |

### 13.2 キャッシュ戦略（開発ルールセクション10.5）

| キャッシュ対象 | 戦略 | TTL | 無効化 |
|--------------|----------|-----|--------------|
| パーソナライズおすすめ結果 | `cache:recommendations:user:{userId}:{hashOfQuery}`（String JSON） | 5分 | 新しいAI分析または商品変更 → `DEL` |
| 類似商品結果 | `cache:recommendations:similar:{productId}`（String JSON） | 5分 | 商品更新/削除 → `DEL` |
| スポンサード広告プール | `cache:recommendations:ads:eligible`（String JSON） | 10分 | 広告承認/却下、支払ステータス変更、または広告期限切れ → `DEL` |
| おすすめ履歴 | キャッシュしない（直接DBクエリ。ユーザーあたり低ボリューム） | — | — |

ルール：
- キャッシュアサイドパターン：Redis確認 → ミス → DBクエリ → Redisシード。
- パーソナライズキャッシュキーは`userId`＋シリアライズ済みクエリパラメータのハッシュでスコープ。
- 分析変更時の無効化はそのユーザーのすべてのキーをパージ（`cache:recommendations:user:{userId}:*`）。
- 常にTTLを設定。機密データはキャッシュしない。

### 13.3 セキュリティ考慮事項

| 考慮事項 | 軽減策 |
|---------|------------|
| フィルタのSQLインジェクション | Prismaパラメータ化クエリ。SQLへの文字列補間なし |
| URLパラメータのXSS | React自動エスケープ。`dangerouslySetInnerHTML`なし |
| 極端に長い成分リスト | 400バリデーションエラー。最大配列長が適用 |
| `productId`の無効UUID | 400バリデーションエラー |
| データ漏洩（未承認ショップ） | クエリレベルで未承認ショップ商品を除外（セクション12.2） |
| 無許可のパーソナライゼーション | JWT必要。おすすめ画面とデータへのアクセスはゲストに拒否 |
| PII／健康データ露出 | 分析画像や肌データはログに記録しない。イベントログの識別子のみ |

### 13.4 レスポンシブデザイン要件

| ブレークポイント | レイアウト |
|------------|--------|
| デスクトップ（≥1024px） | フィルタサイドバー＋結果グリッド（4列） |
| タブレット（768px〜1023px） | フィルタサイドバー（狭い）＋グリッド（2列） |
| モバイル（<768px） | フィルタドロワー＋スタックグリッド（1列） |
