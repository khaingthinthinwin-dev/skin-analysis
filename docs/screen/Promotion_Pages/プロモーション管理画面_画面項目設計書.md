## 2. Screen Overview & Purpose (画面概要・目的)

### 2.1 Purpose (目的)
The Promotion Management screens enable merchants to manage their promotional discount codes (coupons) through full CRUD operations. Merchants can create, edit, delete promotions, toggle active status, and view usage statistics. Buyers can validate and apply coupon codes at checkout. Admin users have full access to all promotions.

### 2.2 Target Users & Roles (対象ユーザーと権限)

| Attribute | Value |
| :--- | :--- |
| **Primary Actors** | Authenticated merchant (own promotions), Admin (all promotions) |
| **Secondary Actor** | Authenticated buyer (coupon validation at checkout) |
| **Restricted Actor** | Pending/rejected merchant (read-only list, no mutations) |
| **Required Authentication** | JWT Bearer Token |
| **Data Scope** | Merchant: own promotions only. Buyer: validate coupons. Admin: all promotions. |
| **Access Control** | Protected routes — JwtAuthGuard + RolesGuard (merchant/admin/buyer) |

### 2.3 Core Functions & Basic Design Principles (主要機能・基本設計方針)
1. **Promotion Listing** — View and manage merchant's promotions with search/filter.
2. **Promotion Creation** — Create new promotions with code, discount type, value, and validity period.
3. **Promotion Editing** — Update existing promotion details (restricted when used_count > 0).
4. **Promotion Deletion** — Hard delete promotions (restricted when used_count > 0).
5. **Status Toggle** — Toggle promotion active/inactive status.
6. **Usage Statistics** — View usage counts and expiry information.
7. **Coupon Validation** — Buyers validate coupon codes at checkout.
8. **Internationalization** — Full i18n support for EN, JA, MY.
9. **Responsive Design** — Mobile-first adaptive layout.

## 5. Item Behaviors & Event Specifications (各項目における挙動・イベント仕様)

### 5.1 Search Promotions (`txtSearch` onChange)
- **Trigger:** User types in search input (debounced 300ms).
- **Processing Logic:**
  1. **Client-Side Pre-Check:** Validate input length ≤ 50.
  2. **Backend Dispatch:** `GET /api/v1/promotions?search={encodedQuery}&status={status}&page=1&limit=20`.
  3. **Backend Execution:** Filter promotions by code containing query string.
  4. **Post-Execution UI:** Update promotion table with filtered results. Reset pagination to page 1.
- **Exception Handling:**
  - Network error: Display "Search failed. Please try again" in toast.

### 5.2 Filter by Status (`selStatusFilter` onChange)
- **Trigger:** User selects status filter option.
- **Processing Logic:**
  1. **Backend Dispatch:** `GET /api/v1/promotions?status={status}&page=1&limit=20`.
  2. **Backend Execution:** Filter promotions by active/inactive/scheduled/expired status.
  3. **Post-Execution UI:** Update promotion table with filtered results. Reset pagination to page 1.
- **Exception Handling:** None applicable.

### 5.3 Add New Promotion (`btnAddPromotion` onClick)
- **Trigger:** User clicks "Add New Promotion" button.
- **Processing Logic:**
  1. Navigate to `/merchant/promotions/new`.
  2. Initialize empty promotion form with default values.
- **Exception Handling:** None applicable.

### 5.4 Edit Promotion (`btnEdit` onClick)
- **Trigger:** User clicks edit button on promotion row.
- **Processing Logic:**
  1. Navigate to `/merchant/promotions/:id/edit`.
  2. Fetch promotion data from `GET /api/v1/promotions/:id`.
  3. Populate form fields with existing promotion data.
- **Exception Handling:**
  - `404`: Display "Promotion not found" and redirect to list.

### 5.5 Delete Promotion (`btnDelete` onClick → `dlgDeleteConfirm` → `dlgDeleteConfirmBtn` onClick)
- **Trigger:** User clicks delete button on promotion row.
- **Processing Logic:**
  1. **Confirmation Dialog:** Display "Are you sure you want to delete this promotion? This action cannot be undone." with Confirm/Cancel buttons.
  2. **On Confirm:** `DELETE /api/v1/promotions/:id`.
  3. **Backend Execution:** Permanently delete promotion record from database (hard delete). Invalidate cache.
  4. **Post-Execution UI:** Remove promotion from list. Show success toast.
- **Exception Handling:**
  - `403`: Display "You don't have permission to delete this promotion".
  - `404`: Display "Promotion not found".
  - `409`: Display "Cannot delete promotion that has already been used".

### 5.6 Toggle Active Status (`swtActive` onChange)
- **Trigger:** User toggles active switch on promotion row.
- **Processing Logic:**
  1. **Backend Dispatch:** `PATCH /api/v1/promotions/:id` with `{ isActive: newValue }`.
  2. **Backend Execution:** Update `is_active` boolean. Invalidate cache.
  3. **Post-Execution UI:** Update status badge. Show success toast.
- **Exception Handling:**
  - `403`: Display "Permission denied". Revert switch state.

### 5.7 Promotion Form Submit (`btnSave` onClick)
- **Trigger:** User clicks "Save Promotion" / "Update Promotion" button.
- **Processing Logic:**
  1. **Client-Side Pre-Check:** Full Zod schema validation — all required fields valid, code unique, dates valid.
  2. **Backend Dispatch:** `POST /api/v1/promotions` (Create) or `PATCH /api/v1/promotions/:id` (Update) with JSON body.
  3. **Backend Execution:** Validate DTO. Check code uniqueness. Validate date range. Create/update promotion record. Invalidate cache.
  4. **Post-Execution UI:** Show success toast. Navigate to `/merchant/promotions`.
- **Exception Handling:**
  - `VAL_001` (400): Display field-specific validation errors inline.
  - `400 PROMO_CODE_DUPLICATE`: Display "A promotion with this code already exists" on code field.
  - `403 MERCHANT_NOT_APPROVED` or `MERCHANT_REJECTED`: Display the matching license restriction banner for restricted merchants.
  - Network error: Display "Network error. Please check your connection".

### 5.8 Cancel Form (`btnCancel` onClick)
- **Trigger:** User clicks "Cancel" button.
- **Processing Logic:**
  1. Navigate to `/merchant/promotions`.
  2. Reset form state.
- **Exception Handling:** None applicable.

### 5.9 Language Toggle (`btnLanguageToggle` onClick)
- **Trigger:** User clicks language toggle button.
- **Processing Logic:**
  1. Cycle through languages: EN → JA → MY → EN.
  2. Update `i18next` language via `i18n.changeLanguage()`.
  3. Persist preference to `localStorage`.
  4. Re-render all translated labels.
- **Exception Handling:** None applicable.

### 5.10 Theme Toggle (`btnThemeToggle` onClick)
- **Trigger:** User clicks theme toggle button.
- **Processing Logic:**
  1. Cycle through themes: light → dark → system.
  2. Update `next-themes` theme via `setTheme()`.
  3. Persist preference to `localStorage`.
- **Exception Handling:** None applicable.

### 5.11 Pagination (`btnPrevPage` / `btnNextPage` / `btnPageNumbers` onClick)
- **Trigger:** User clicks pagination controls.
- **Processing Logic:**
  1. **Backend Dispatch:** `GET /api/v1/promotions?page={page}&limit=20`.
  2. **Backend Execution:** Fetch promotions for requested page.
  3. **Post-Execution UI:** Update promotion table and pagination display.
- **Exception Handling:** None applicable.

### 5.12 Restricted Merchant Page Load Behavior (`bannerLicenseRestricted` on page load)
- **Trigger:** Merchant navigates to `/merchant/promotions` with `licenseStatus === 'pending'` or `licenseStatus === 'rejected'`.
- **Processing Logic:**
  1. **Backend Dispatch:** `GET /api/v1/promotions` (promotion list API).
  2. **Backend Execution:** Return promotion list data (same as approved merchants).
  3. **Frontend License Check:** Fetch merchant profile. Check `licenseStatus`.
    4. **If `pending` or `rejected`:**
      - Display `bannerLicenseRestricted` at top of page. For rejected merchants, include the rejection reason when available.
      - Hide all CRUD buttons: `btnAddPromotion`, `btnEdit`, `btnDelete`, `swtActive`.
      - Keep functional: `txtSearch`, `selStatusFilter`, pagination controls.
      - Promotion table displays in read-only mode (data visible, no action buttons).
  5. **If `approved`:** Full access (default behavior).
- **Exception Handling:**
  - `401`: Redirect to login.
  - `403`: Display permission error.

## 11. Special UI Notes & Styling Constraints (特記事項・UI仕様)

- **Design System:** Luxury Cosmetics Theme — Primary `#7C3AED` (Purple), Accent `#EC4899` (Pink), Secondary `#F3E8FF` (Lavender).
- **Responsive Viewport Design:** Full-width form on all breakpoints. Table scrolls horizontally on mobile.
- **Accessibility:** Every control must be keyboard navigable. ARIA labels required. Error messages must be announced via `role="alert"`.
- **Performance:** Promotion list uses skeleton loaders during initial load. Buttons display spinner during async operations.
- **Security:** All user input is sanitized to prevent XSS. Never trust client-side validation alone.
- **Design Tokens:** Status badges use standard color mapping — success: `bg-green-100 text-green-800`, error: `bg-red-100 text-red-800`, warning: `bg-amber-100 text-amber-800`, info: `bg-blue-100 text-blue-800`.
- **Discount Type Badges:** Percentage: `bg-blue-100 text-blue-800`. Fixed: `bg-green-100 text-green-800`.
- **Code Field Styling:** Monospace font (`font-mono`) for promotion codes to improve readability.
