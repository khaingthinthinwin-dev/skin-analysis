## 2. 画面概要・目的

### 2.1 目的
検索・フィルタページは、Cosmetics Finderプラットフォームにおけるディスカバリーおよび探索のエントリーポイントです。全ユーザー（ビジター、バイヤー、マーチャント、管理者）がキーワード検索、階層カテゴリナビゲーション、多次元フィルタ（肌タイプ、成分、価格帯、レビュー評価）を通じてスキンケア商品を特定できるようにします。検索結果はソート、ページネーションが可能で、設定可能なグリッドまたはリストレイアウトでレンダリングされます。すべての検索、フィルタ、ソート、ページネーション状態はURLクエリパラメータに永続化され、権威ある状態ソースとして機能し、結果セットの共有、ブックマーク、ナビゲーション互換性を確保します。

### 2.2 対象ユーザーと権限

| 属性 | 値 |
| :--- | :--- |
| **主たるアクター** | 全ロール — ビジター（未認証）、バイヤー（認証済み）、マーチャント（認証済み）、管理者（認証済み） |
| **認証要件** | 検索/閲覧/フィルタ/ソート/ページネーションには不要（公開エンドポイント）。ショッピングアクション（カート/ウィッシュリスト追加）は認証が必要。 |
| **データスコープ** | グローバル商品カタログ（承認済みマーチャントショップの有効・承認済み商品） |
| **アクセス制御** | 公開ルート — 検索/フィルタ/ソート/ページネーションには認証ガードなし。ショッピングアクションは制限: バイヤー ✓、ゲスト → アラートモーダル（自動クローズなし） → `/login?redirect=<path>`、マーチャント/管理者 → 403 `SHOPPING_NOT_ALLOWED`。公開検索エンドポイントにレート制限を適用。 |

### 2.3 主要機能・基本設計方針
1. **キーワード検索** — 商品名、短い説明、タグ、成分フィールドに対する部分的（大文字小文字不区別）マッチング。
2. **カテゴリ閲覧** — 単一選択フィルタ付きの階層カテゴリツリーナビゲーション。結果にすべての子孫カテゴリを含む。
3. **多次元フィルタ** — 肌タイプ（複数選択）、成分（複数選択）、価格帯（最小/最大範囲）、最低レビュー評価（1〜5星）による同時フィルタリング。
4. **ソート** — 新着順、価格（安い順/高い順）、評価が高い順でソート可能。
5. **ページネーション** — 設定可能なページサイズ（10、20、50件/ページ; デフォルト20; 最大100）付きのページング結果。
6. **URL状態ナビゲーション** — すべての検索/フィルタ/ソート/ページ状態がURLクエリパラメータにシングルソースオブトゥルースとしてエンコード（BR-SEARCH-003）。ブラウザの戻る/進むおよびURL共有をサポート。
7. **パフォーマンスキャッシュ** — 繰り返しクエリとカテゴリツリーはRedisキャッシュから提供（商品リストTTL 2分、カテゴリツリーTTL 30分）。
8. **レスポンシブデザイン** — デスクトップ: 固定フィルタサイドバー+マルチカラム商品グリッド。モバイル: ボトムシートフィルタドロワー+シングルカラム商品表示。
9. **表示モード切替** — レスポンシブグリッド（1〜4カラム、アダプティブ）とモバイル最適化リスト（シングルカラム積み重ね行）の間で結果レイアウトを切り替え。選択はlocalStorageに永続化、デフォルトはグリッド、URL状態に影響せず再取得をトリガーしない。
10. **スポンサー広告** — マーチャントが購入した広告パッケージから承認済み広告画像/バナーを`GET /api/v1/ads?placement=search_top`で取得し、検索結果トップ配置に5分Redis TTLで表示。対象広告（最大5件）は、ページヘッダー（[A]）と検索バー+フィルタ行（[B]+[C]）の間に全コンテナ幅で水平中央にスライドダウンパネルに表示され、アニメーション付きスライドダウンエントランス、各スライドにタイトル、説明、画像/バナー、CTAを一緒に表示、デスクトップではレスポンシブ水平レイアウト、モバイルではスタックレイアウトで、商品結果をブロックせずに5秒ごとに自動スライド。

### 3.2 レスポンシブレイアウトブレークポイント

| ブレークポイント | 最小幅 | レイアウト動作 |
| :--- | :--- | :--- |
| モバイル（デフォルト） | 0px | 検索バー（[B]）とフィルタトリガーボタン（[C]）が同じ行に。フィルタはボトムシート/オーバーレイドロワーとして開く。グリッド表示: 1〜2カラム; リスト表示: 積み重ね行。グリッド/リスト表示切替は結果ツールバーに（localStorageに永続化）。フィルタチップ行は結果の上に。スポンサー広告スライドダウンパネル（`slotAdTop`）はページヘッダーと検索バー+フィルタ行の間に全コンテナ幅でスタック: 全幅16:9画像が上、タイトル、説明、全幅CTAが下に。結果エリア（[D]）は検索+フィルタ行の下に。 |

### 5.1 キーワード入力（`txtSearch`のonInput / onKeyDown）
- **トリガー:** ユーザーが検索入力に文字を入力。
- **処理ロジック:**
  1. **デバウンス:** タイピング停止300ms後にのみクエリを発行（ST-DEB-001）。各キーストロークでタイマーをリセット（ST-DEB-002）。
  2. **URL更新:** `setSearchParams`で`q`クエリパラメータを更新。
  3. **再取得:** TanStack Queryが新しいキーで`GET /api/v1/products`を再取得。
  4. **状態遷移:** デバウンスクエリ発火時に`IDLE` → `LOADING`が発生（ST-DEB-005）。
  5. **上書き:** 前のリクエストがインフライアットの場合、キャンセル/無視; 最新の状態のみレンダリング（ST-DEB-004）。
  6. **Enterキー:** Enterを押すとデバウンスをバイパスしてクエリを即座に発火。
- **例外処理:** 無効/欠落したパラメータは`searchParamsSchema`（Zod）でキャッチ; 無効な値はドロップまたは`alertError`で表示。

### 5.2 検索ボタン（`btnSearch`のonClick）
- **トリガー:** ユーザーが検索ボタンをクリック。
- **処理ロジック:**
  1. デバウンスタイマーを待たずに現在の`txtSearch`値を即座に送信（ST-DEB-003）。
  2. `q`パラメータを更新し再取得。
- **例外処理:** キーワードが255文字を超える場合は`VAL-SEARCH-001`で拒否。

### 5.3 検索クリア（`btnClearSearch`のonClick）
- **トリガー:** ユーザーが検索クリアボタンをクリック。
- **処理ロジック:**
  1. URLから`q`パラメータをクリア。
  2. `txtSearch`を空にリセット。
  3. デフォルトカタログを再取得（`createdAt desc`でソート）。
- **例外処理:** 該当なし。

### 5.4 カテゴリチェックボックス変更（`chkCategory`のonChange）
- **トリガー:** ユーザーがネストされたツリーでカテゴリをチェック/チェック解除。
- **処理ロジック:**
  1. `categoryId`パラメータを設定/クリア。
  2. `page`を1にリセット（BR-SEARCH-011）。
  3. 再取得 — バックエンドはすべての子孫カテゴリを含む（BR-SEARCH-010）。
- **例外処理:** 無効なUUIDは`VAL-SEARCH-002` / `VAL-SEARCH-013`で拒否。

### 5.5 フィルタを適用（`btnApplyFilters`のonClick）
- **トリガー:** ユーザーが「フィルタを適用」ボタンをクリック（またはモバイルドロワーで適用）。
- **処理ロジック:**
  1. 変更されたフィルタを収集（skinTypes、ingredients、minPrice、maxPrice、rating、categoryId）。
  2. 数値フィールドをバリデーション（min ≥ 0、max ≥ 0、min ≤ max）。
  3. 現在のパラメータに`page: 1`でマージ（BR-SEARCH-011）。
  4. `setSearchParams(toQueryString(...))`。
  5. TanStack Queryが再取得; フェッチ中にグリッドがスケルトンを表示。
  6. モバイル: フィルタドロワーを閉じる。
- **例外処理:** 無効な値はフィールドごとにインライン表示（セクション6.1参照）。無効な場合、クエリは発火しない。

### 5.6 フィルタをリセット（`btnResetFilters`のonClick）
- **トリガー:** ユーザーが「フィルタをリセット」ボタンをクリック（パネル、空状態、またはモバイルドロワー）。
- **処理ロジック:**
  1. すべてのフィルタパラメータを削除（`categoryId`、`skinTypes`、`ingredients`、`minPrice`、`maxPrice`、`rating`）。
  2. キーワード`q`は保持。
  3. `page`を1にリセット（BR-SEARCH-011）。
  4. デフォルト結果セットを再取得（BR-SEARCH-023）。
- **例外処理:** 該当なし。

### 5.7 ソート変更（`selSort`のonChange）
- **トリガー:** ユーザーが新しいソートオプションを選択。
- **処理ロジック:**
  1. オプションを`sort` + `order`パラメータにマッピング（`price/asc`、`price/desc`、`rating/desc`、`createdAt/desc`）。
  2. `page`を1にリセット。
  3. TanStack Queryで再取得; 新しい順序でグリッドを再レンダリング。
- **例外処理:** 許可リストにない値は拒否（BR-SEARCH-015、`VAL-SEARCH-009`/`VAL-SEARCH-010`）。

### 5.8 ページネーションおよびページサイズ（`pgnPagination` / `selPageSize`のonClick / onChange）
- **トリガー:** ユーザーがページ番号、前へ/次へをクリック、またはページサイズを変更。
- **処理ロジック:**
  1. **ページ変更:** `page`パラメータを更新; `keepPreviousData`で再取得。
  2. **ページサイズ変更:** `limit`パラメータを更新し、`page`を1にリセット。
  3. 新しいページの結果をレンダリング。
  4. `page > totalPages`の場合は最後のページにクランプ、または空状態を表示（セクション3.3）。
  5. 境界処理: 最初のページでは前へを無効化、最後のページでは次へを無効化。
- **例外処理:** `page < 1`または`limit > 100`は拒否（`VAL-SEARCH-011`、`VAL-SEARCH-012`）。

### 5.9 アクティブフィルタチップ削除（`chipFilter`の×onClick）
- **トリガー:** ユーザーがフィルタチップの閉じる（×）アイコンをクリック。
- **処理ロジック:**
  1. URLパラメータからその単一フィルタ値を削除。
  2. `page`を1にリセット（BR-SEARCH-022）。
  3. 再取得。
- **例外処理:** 該当なし。

### 5.10 すべてのフィルタをクリア（`btnClearAllFilters`のonClick）

- **処理ロジック:**
  1. すべてのアクティブフィルタを一度に削除（BR-SEARCH-023）。
  2. キーワード`q`は保持。
  3. `page`を1にリセット; デフォルト結果セットを再取得。
- **例外処理:** 該当なし。

### 5.11 モバイルフィルタドロワー（`btnMobileFilter`のonClick）
- **トリガー:** ユーザーがモバイルの検索+フィルタ行でフィルタトリガーボタンをクリック。
- **処理ロジック:**
  1. `pnlFilters`をボトムシート/オーバーレイドロワーとして開く。
  2. フォーカストラップ + `aria-modal`を適用。
  3. 「フィルタを適用」で適用してドロワーを閉じる。
  4. 閉じる（X）ボタンは保留中の変更を適用せずに閉じる。
- **例外処理:** 該当なし。

### 5.12 言語切替（`btnLanguageToggle`のonClick）
- **トリガー:** ユーザーが言語切替ボタンをクリック。
- **処理ロジック:**
  1. 言語を循環: EN → JA → MY → EN。
  2. `i18n.changeLanguage()`で`i18next`言語を更新。
  3. 設定を`localStorage`に永続化。
  4. 全翻訳ラベルを再レンダリング。
- **例外処理:** 該当なし。

### 5.13 テーマ切替（`btnThemeToggle`のonClick）
- **トリガー:** ユーザーがテーマ切替ボタンをクリック。
- **処理ロジック:**
  1. テーマを循環: light → dark → system。
  2. `next-themes`の`setTheme()`でテーマを更新。
  3. 設定を`localStorage`に永続化。
- **例外処理:** 該当なし。

### 5.14 表示モード切替（`tglViewMode` / `btnGridMode` / `btnListMode`のonClick）
- **トリガー:** ユーザーが結果ツールバーの「グリッド」または「リスト」セグメントボタンをクリック。
- **処理ロジック:**
  1. `tglViewMode`をクリックした値に設定（`grid`または`list`）。
  2. すでに取得済みの`data`を使用して選択されたレイアウトで`gridProducts` / `cardProduct` / `sklLoading`を再レンダリング — API再取得はトリガーしない。
  3. すべてのURLクエリパラメータは変更しない（`q`、`categoryId`、`skinTypes`、`ingredients`、`minPrice`、`maxPrice`、`rating`、`sort`、`order`、`page`、`limit`）。検索、フィルタ、ソート、ページネーション状態は変更なし; ページ位置はリセットされない。
  4. 選択を`localStorage`キー`search.viewMode`に永続化。ページ読み込み時に保存された値を復元; 不存在または無効な場合は`grid`（グリッド表示）にフォールバック。
- **例外処理:** 該当なし（ローカルUI状態のみ）。無効な保存値はサイレントに`grid`にフォールバック。

### 5.15 スポンサー広告表示（`slotAdTop`のマウント時）
- **トリガー:** コンポーネントマウント（検索・フィルタページ読み込み）。
- **処理ロジック:**
  1. **広告スロット取得:** `GET /api/v1/ads?placement=search_top` — 商品結果のフェッチと並行、商品読み込みをブロックまたは延期しない。
  2. **フィルタリング:** 検索結果トップ配置のマーチャント購入広告パッケージから承認済み広告レコードを選択。現在時刻をカバーする承認済み、有効、スケジュール内の広告のみ保持。
  3. **優先度:** パッケージ配置およびティア優先度ルールを適用（Premium > Standard > Basic）、ティア内ラウンドロビンローテーション、その後スライダーを最大5広告に制限。
  4. **キャッシュ:** 結果の広告リストをRedisにキー`cache:ads:search-top`、TTL 5分でキャッシュ（BR-SEARCH-028）。
  5. **スライドダウンエントランス:** 対象広告が存在する場合、`slotAdTop`はページヘッダー（[A]）と検索バー+フィルタ行（[B]+[C]）の間に全コンテナ幅で水平中央にスライドダウン — 高さを0から展開しながらパネルが−100%から0に翻訳（300ms ease-out、マウントごとに1回）、検索バー+フィルタ行と商品グリッドをスムーズに下に押し出す。`prefers-reduced-motion: reduce`の場合、アニメーションなしで瞬時に表示。
  6. **スライドコンテンツのレンダリング:** 各スライドは広告の画像/バナー（`imgAdBanner`）、タイトル（`lblAdTitle`）、説明（`txtAdDescription`、存在しない場合は非表示）、CTA（`btnAdCta`）を1つの`cardAdSlide`で一緒にレンダリングし、すべてのスライドに「スポンサー広告」バッジ（`badgeSponsored`）を追加（REQUIREMENT_SPEC §5.3）。説明は2行にクランプ; タイトルは1行に切り詰め。
  7. **自動スライド:** 垂直スライドダウン遷移（現在のスライドが上に退出、次が上から入る、500ms）で5秒ごとに次の広告に進行。最大5スライド; 最後から最初にループ。
  8. **レスポンシブレイアウト:** デスクトップ/タブレット（≥ 768px）: 水平スライド — 画像が左（320×120、object-cover）、テキストブロックが右、インラインCTA。モバイル（< 768px）: スタックスライド — 全幅16:9画像、タイトル、説明、下に全幅CTA。全ブレークポイントでパネルは全コンテナ幅、[A]と[B]+[C]行の間に水平中央。レイアウト切替はCSSのみ（ブレークポイント）; ブレークポイント越境時の再取得なし、ローテーションリセットなし。
  9. **インタラクション時の一時停止:** ポインタがホバー中、またはキーボードフォーカスが`slotAdTop`内にある間は自動進行を一時停止; ポインタ離脱/ブラーで再開（WCAG 2.2.2）。5秒間隔自体は変更なし。
  10. **エラー処理:** 広告取得エラーまたは空レスポンスの場合、`slotAdTop`を完全に非表示 — スライドダウンエントランスは実行されない（グレースフルデグレダーション; 広告の失敗は商品結果をブロックしない）。
  11. **クリックトラッキング:** CTAクリックで`ad_id`と`placement`で`ad.click`分析イベントを発火。
- **例外処理:** なし（広告スロットの失敗は非クリティカル; ページは広告なしでも正常に機能）。

## 11. 特記事項・UI仕様

- **デザインシステム:** 奢侈コスメティックテーマ — プライマリ `#7C3AED`（パープル）、アクセント `#EC4899`（ピンク）、セカンダリ `#F3E8FF`（ラベンダー）。
- **URL状態シングルソースオブトゥルース:** すべての検索/フィルタ/ソート/ページ状態はURLクエリパラメータに永続化（BR-SEARCH-003）。戻るボタンおよびURL共有フレンドリー。
- **レスポンシブビューポートデザイン:** デスクトップ: 検索バー+フィルタがサイドバイサイドで同じ行に、結果は4カラムグリッドの下に; タブレット: 検索バー+コンパクトフィルタが同じ行に、2〜3カラム結果; モバイル: 検索バー+フィルタトリガーが同じ行に、フィルタドロワー+1〜2カラム結果（セクション3.2）。
- **アクセシビリティ:** 全コントロールはキーボードナビゲーション可能。ARIAラベル必須。ドロワーはフォーカストラップ+`aria-modal`を使用。エラーメッセージは`role="alert"`でアナウンス。チップは削除をアナウンス。
- **表示モード切替:** `selSort`の横にある結果ツールバーのセグメントグリッド/リストコントロール。グリッドはレスポンシブ1〜4カラムカードレイアウトをレンダリング; リストはシングルカラム積み重ね行（サムネイル左、タイトル/説明/価格右）を狭いビューポートに最適化 — 水平スクロールなし、長いテキストは切り詰め。選択はデバイス非依存、`localStorage`（`search.viewMode`）に永続化、デフォルトはグリッド、URLにシリアライズされないため、検索/フィルタ/ソート/ページネーション状態に影響なし。
- **表示切替アクセシビリティ:** `tglViewMode`は`role="group"`で表示ラベル付きでレンダリング; 各セグメントは`aria-pressed`がアクティブモードを反映し`aria-label`（i18n）を持つフォーカス可能ボタン。フォーカスインジケーターはプライマリカラーリングを使用。キーボード（Tab / Enter / Space; グループ内の矢印キーナビゲーション）およびタッチ（ターゲット≥ 44px）で操作可能。アクティブモードの変更は`aria-live="polite"`でスクリーンリーダーにアナウンス。
- **パフォーマンス:** フェッチ中のスケルトンシマーグリッド; キーワード入力で300msデバウンス; TanStack Queryキャッシュ; ページネーションで`keepPreviousData`。キャッシュアサイドRedisパターン（リストTTL 2分、カテゴリツリーTTL 30分）。
- **セキュリティ:** 全ユーザー入力はサニタイズ（Prismaパラメータ化クエリ; React自動エスケープ）。レスポンスボディ全体はログに記録しない。公開検索にレート制限。
- **デザイントークン:** ステータスバッジは標準カラーマッピングを使用 — 成功: `bg-green-100 text-green-800`、エラー: `bg-red-100 text-red-800`、警告: `bg-amber-100 text-amber-800`。評価星はビューティピンクを使用。
- **ゲストアラートモーダル（401）:** ゲスト（未認証ユーザー）がショッピングアクション（カート/ウィッシュリスト追加）を試みた場合、"ログインしてください"メッセージと"OK"ボタンのアラートモーダルを表示。モーダルは自動クローズしてはならない。"OK"をクリックすると`/login?redirect=<encoded_current_path>`にリダイレクト。リダイレクトはログイン後にユーザーの検索コンテキストを保持。
- **マーチャント/管理者ショッピング制限（403）:** マーチャントまたは管理者ユーザーがショッピングアクション（カート/ウィッシュリスト追加）を試みた場合、"買い物機能はバイヤーのみ利用できます"メッセージのアラートバナーを表示。バナーは自動クローズしてはならない。マーチャント/管理者ユーザーはDEVELOPMENT_RULESセクション5.4によりショッピング機能を厳密に禁止。
- **スポンサー広告スライドダウンパネル:** `slotAdTop`はページヘッダー（[A]）と検索バー+フィルタ行（[B]+[C]）の間に全コンテナ幅で水平中央にスライドダウンパネルとしてレンダリング — 対象広告がロードされると下に展開（高さ0 → auto、translateY −100% → 0、300ms ease-out、マウントごとに1回）、検索バー+フィルタ行と下の全コンテンツをスムーズに下に押し出す。広告取得エラーまたは対象広告なしの場合は完全に非表示 — スライドダウンなし。広告取得は商品結果とは独立 — 商品読み込みをブロックまたは延期しない。
- **広告スライド構成:** 全スライドは広告の画像/バナー、タイトル、説明、CTAボタン、"スポンサー"バッジを一緒に表示（REQUIREMENT_SPEC §5.3）。タイトルは1行に切り詰め; 説明は2行にクランプ、存在しない場合は非表示。スライド遷移は5秒間隔で垂直スライドダウン（500ms）（最大5広告、ティア優先度+ラウンドロビンは変更なし）。
- **広告パネルレスポンシブ性:** 全ブレークポイントでパネルは全コンテナ幅、[A]と[B]+[C]行の間に水平中央、[B]+[C]はその直下。デスクトップ/タブレット（≥ 768px）: 水平スライド — 画像320×120（`object-cover`）が左、テキストブロックが右、インライン右寄せCTA。モバイル（< 768px）: スタックスライド — 全幅16:9画像、タイトル、説明、下に全幅CTA。ブレークポイント切替はCSSのみ: 再取得なし、ローテーションリセットなし。
- **広告パネルアクセシビリティ:** コンテナは`role="region"` + `aria-label`（`search.sponsored.panelLabel`）を公開。ホバー中およびキーボードフォーカスがパネル内にある間は自動進行を一時停止、離脱/ブラーで再開（WCAG 2.2.2）。スライド変更は`aria-live="polite"`で`search.sponsored.slideStatus`を使用してアナウンス。画像は`search.sponsored.adAlt`から説明的な`alt`を持つ。CTAは可见プライマリフォーカスリング付きのフォーカス可能リンク; 全スライドクリックエリアはキーボードユーザーをトラップしてはならない。`prefers-reduced-motion: reduce`はエントランスおよびスライド遷移を無効化（瞬時スワップ; 5秒間隔は変更なし）。
- **ゲストデータ漏洩:** ゲストユーザーの検索状態（フィルタ、キーワード）はセッション間で永続化してはならない。ショッピング関連データ（カート数、ウィッシュリスト）はゲストに公開しない。
