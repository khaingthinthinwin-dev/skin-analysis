## 1. 機能概要

### 1.1 目的と範囲

本画面は、Cosmetics Finderプラットフォームにおける商品の発見・探索のエントリーポイントとして機能します。検索・フィルタサブシステムは、購入者がキーワードでスキンケア商品を探し、階層型カテゴリツリーを閲覧し、多次元フィルタ（肌タイプ、成分、価格帯、最低評価）を適用し、結果を並び替え、カタログをページ送りするために必要なすべての機能を提供します。

本サブシステムは商品閲覧と商品詳細を橋渡しします。承認済みの出品者ショップから適切に検証されたアクティブ商品のみが購入者に表示されることを保証するとともに、Redisリストキャッシュと、共有可能でブラウザの戻るボタンに対応したURL状態駆動のフロントエンドナビゲーションによりパフォーマンスを維持します。

### 1.2 機能責任

本画面は以下のコア機能領域を担当します：

1. **キーワード検索** — 購入者が名前、短い説明、タグ、成分の部分一致（大文字小文字を区別しない）で商品を検索できるようにする。
2. **カテゴリ閲覧** — 購入者がネストされたカテゴリツリーを操作し、すべての子孫カテゴリを含むカテゴリでフィルタできるようにする。
3. **多次元フィルタリング** — 購入者が肌タイプ、成分、価格帯、最低レビュー評価で商品をフィルタできるようにする。
4. **並び替え** — 購入者が価格、平均評価、または新着順で結果を並び替えできるようにする。
5. **ページネーション** — 購入者が結果をページ送りできるようにする（デフォルト20件、最大100件）。
6. **商品の発見** — アクティブで出品者承認済み、在庫ありまたは在庫切れフラグ付きの商品カードを提示し、商品詳細へリンクする。
7. **URL状態ナビゲーション** — すべての検索／フィルタ／並び替え／ページ状態をURLクエリパラメータに単一の真実のソースとして保持する。
8. **キャッシュ** — 繰り返しの検索とカテゴリツリーをRedisから提供し、パフォーマンス目標を達成する。

### 1.3 対象ユーザー

| 属性 | 値 |
|------|-----|
| **プライマリアクター** | ビジター（未認証）および購入者（認証済み） |
| **必要認証** | なし（パブリックエンドポイント） |
| **データスコープ** | グローバル商品カタログ（承認済み出品者ショップのアクティブ商品） |
| **ゲストの動作** | 認証なしで検索、閲覧、フィルタ、並び替え、ページネーションがすべて利用可能。結果クリックからの商品詳細もパブリック。 |

### 1.5 入力／出力

| 入力情報 | データカテゴリ | ソース／説明 |

| `order` | クエリパラメータ | 並び順（`asc`、`desc`） |

## 3. 状態遷移仕様

### 3.1 検索UIセッション状態

| 状態 | 説明 | 結果表示 | 利用可能なアクション |
|------|------|:--------:|---------------------|
| `IDLE` | ページ読み込み済み、クエリ実行中ではない | ✓（デフォルトカタログ） | 検索、フィルタ、並び替え、ページ送り |
| `LOADING` | クエリ実行中 | スケルトングリッド | 新しいクエリ（実行中を置き換え） |
| `SUCCESS` | クエリが正常に返った | ✓ | 並び替え、フィルタ、ページ送り、詳細表示 |
| `EMPTY` | クエリがゼロ件を返した | 空状態 | フィルタリセット、キーワード拡大 |
| `ERROR` | クエリが失敗した（ネットワーク/5xx） | エラーバナー | リトライ |

### 3.2 クエリライフサイクル遷移

| 遷移ID | 遷移元状態 | 遷移先状態 | トリガーアクション | ガード条件 |
|--------|-----------|-----------|-------------------|-----------|
| TR-SEARCH-01 | `IDLE` | `LOADING` | 300msデバウンス後のキーワード入力（第3.4節）またはフィルタ／並び替え／ページ変更 | 有効なURLパラメータ |
| TR-SEARCH-02 | `LOADING` | `SUCCESS` | フェッチが200で解決 | データが返却された |
| TR-SEARCH-03 | `LOADING` | `EMPTY` | フェッチが`total = 0`で解決 | 一致する商品がない |
| TR-SEARCH-04 | `LOADING` | `ERROR` | フェッチが拒否（ネットワーク/4xx/5xx） | エラーレスポンス |
| TR-SEARCH-05 | `SUCCESS` | `LOADING` | フィルタ／並び替え／ページ変更 | パラメータが変更された |
| TR-SEARCH-06 | `EMPTY` | `LOADING` | フィルタリセットまたは新しいキーワード | パラメータが変更された |
| TR-SEARCH-07 | `ERROR` | `LOADING` | リトライクリック | — |

### 3.3 ページネーション境界状態

| 状態 | 説明 | 動作 |
|------|------|------|
| `FIRST_PAGE` | `page = 1` | 前へボタンが無効 |
| `MID_PAGES` | `1 < page < totalPages` | 両方のナビゲーションボタンが有効 |
| `LAST_PAGE` | `page = totalPages` | 次へボタンが無効 |
| `PAGE_BEYOND_RANGE` | `page > totalPages` | 最終ページまたは空状態にクランプ |

### 3.4 検索入力デバウンスルール

| ルールID | ルール名 | 説明 | 適用レイヤー |
|---------|---------|------|-------------|
| ST-DEB-001 | デバウンス付きキーワードトリガー | 検索バーへの入力では、キーストロークごとにAPI呼び出しを行わない。検索リクエストは、タイピングが300ms（0.3秒）途切れた後にのみ発火し、最終的なキーワード値を送信する。 | フロントエンド（デバウンスユーティリティ） |
| ST-DEB-002 | デバウンスタイマーリセット | 300msのウィンドウ内の各キーストロークでデバウンスタイマーをリセットし、中断のないアイドルが300ms続いた後にのみクエリをトリガーする。 | フロントエンド（デバウンスユーティリティ） |
| ST-DEB-003 | 即時アクションのバイパス | デバウンスはタイピングにのみ適用される。検索ボタン（EL-03）、クリア検索（EL-04）、フィルタ／並び替え／ページ変更は待たずに即時発火する。 | フロントエンド（イベントハンドラ） |
| ST-DEB-004 | 実行中クエリの優先 | 前のリクエストがまだ実行中にデバウンス付きクエリが発火した場合、前のリクエストはキャンセル／無視され、最新の状態のみが描画される。 | フロントエンド（TanStack Query） |
| ST-DEB-005 | 発火時の`LOADING` | `IDLE` → `LOADING`遷移は、デバウンス付きクエリが実際に発火したとき（300msのアイドル後）に発生し、タイピング中には発生しない。 | フロントエンド（状態マシン） |

## 4. ビジネスルール

### 4.1 検索ルール

| ルールID | ルール名 | 説明 | 適用レイヤー |
|---------|---------|------|-------------|
| BR-SEARCH-001 | 部分キーワード一致 | キーワードは`name`、`short_description`、`tags`、または`ingredients`に一致する（大文字小文字を区別しない、ORセマンティクス）。 | バックエンド（Prisma `contains`） |

## 6. 機能操作仕様

### 6.1 操作：商品検索

| 属性 | 仕様 |
|------|------|
| **トリガー** | キーワード入力（デバウンス後）、フィルタ／並び替え／ページ変更、またはページ読み込み |
| **APIエンドポイント** | `GET /api/v1/products` |
| **リクエストContent-Type** | クエリパラメータのみ |
| **送信前バリデーション** | URLパラメータをZod（`searchParamsSchema`）でパース・バリデーション。バックエンドDTOはValidationPipeでバリデーション |
| **処理ステップ** | 1. `ProductQueryDto`をバリデーション（whitelist + forbidNonWhitelisted）。2. Redisルックアップ `cache:products:list:{hashOfQuery}`。3. HIT → キャッシュJSONを返却（TTL 2分）。4. MISS → Prisma WHERE句を構築（is_active、承認済みショップ、q、カテゴリサブツリー、skinTypes `hasEvery`、ingredients `hasSome`、価格帯、評価）。5. 並び替え／順序を適用（idx_products_price、idx_products_created_at）。6. skip/takeページネーションを適用。7. トランザクションで`findMany` + `count`を実行。8. Decimalのpriceを文字列としてシリアライズ。9. Redisに投入（TTL 2分）。10. `{ data, meta }`を返却。 |
| **成功レスポンス** | 200 OK、`{ data: ProductSummary[], meta }` |
| **事後アクション** | 商品グリッド、結果件数、ページネーションを描画 |

### 6.2 操作：カテゴリツリーの閲覧

| 属性 | 仕様 |
|------|------|
| **トリガー** | 検索ページの読み込み |
| **APIエンドポイント** | `GET /api/v1/categories` |
| **リクエストContent-Type** | なし |
| **送信前バリデーション** | なし（パブリック） |
| **処理ステップ** | 1. Redisルックアップ `cache:categories`。2. HIT → キャッシュツリーを返却（TTL 30分）。3. MISS → `prisma.category.findMany({ orderBy: { sortOrder: 'asc' } })`。4. `parent_id`自己参照からツリーを構築。5. Redisに投入（TTL 30分）。6. `{ data: tree }`を返却。 |
| **成功レスポンス** | 200 OK、`{ data: CategoryNode[] }` |
| **事後アクション** | フィルタパネルにネストされたカテゴリチェックボックスを描画 |

### 6.3 操作：フィルタ適用

| 属性 | 仕様 |

## 7. 入力／出力仕様

### 7.1 入力定義 — 検索クエリ

| フィールド | 表示名（EN） | 表示名（JA） | データ型・長さ | 必須 | バリデーション |
|-----------|-------------|-------------|---------------|:----:|----------------|
| `q` | Keyword | キーワード | VARCHAR(255) | 任意 | `@IsOptional()`、`@MaxLength(255)` |
| `categoryId` | Category | カテゴリ | UUID | 任意 | `@IsOptional()`、UUID形式 |
| `skinTypes` | Skin Type | 肌タイプ | TEXT[]（カンマ区切り） | 任意 | `@IsOptional()`、enum：dry/oily/combination/sensitive/normal |
| `ingredients` | Ingredients | 成分 | TEXT[]（カンマ区切り） | 任意 | `@IsOptional()`、`@IsArray()` |
| `tags` | Tags | タグ | TEXT[]（カンマ区切り） | 任意 | `@IsOptional()` |
| `minPrice` | Minimum Price | 最低価格 | NUMERIC(10,2) | 任意 | `@IsOptional()`、`@Min(0)` |
| `maxPrice` | Maximum Price | 最高価格 | NUMERIC(10,2) | 任意 | `@IsOptional()`、`@Min(0)` |
| `rating` | Minimum Rating | 最低評価 | NUMERIC(3,2) | 任意 | `@IsOptional()`、`@Min(1)`、`@Max(5)` |
| `sort` | Sort Field | 並び順項目 | ENUM | 任意（デフォルト：`createdAt`） | `@IsIn(['price', 'rating', 'createdAt'])` |
| `order` | Sort Direction | 並び順 | ENUM | 任意（デフォルト：`desc`） | `@IsIn(['asc', 'desc'])` |
| `page` | Page | ページ | INTEGER | 任意（デフォルト：1） | `@IsOptional()`、`@Min(1)` |
| `limit` | Items Per Page | 1ページあたりの件数 | INTEGER | 任意（デフォルト：20） | `@IsOptional()`、`@Min(1)`、`@Max(100)` |

**リクエスト例：**

```
GET /api/v1/products?q=cleanser&skinTypes=oily&minPrice=10&maxPrice=50&rating=4&sort=price&order=asc&page=1&limit=20
```

## 8. 入力バリデーションルール

### 8.1 検索クエリバリデーション（厳格モード）

| フィールド | バリデーションルール | エラーメッセージ（EN） | エラーメッセージ（JA） |
|-----------|---------------------|------------------------|------------------------|
| `q` | 任意、最大255文字 | "Keyword must be 255 characters or fewer" | "キーワードは255文字以内である必要があります" |
| `categoryId` | 任意、有効なUUID形式 | "Invalid category ID" | "無効なカテゴリIDです" |
| `skinTypes` | 任意、有効なenum値 | "Invalid skin type" | "無効な肌タイプです" |
| `ingredients` | 任意、文字列の配列 | "Invalid ingredients" | "無効な成分です" |
| `minPrice` | 任意、≥ 0 | "Minimum price must be 0 or more" | "最低価格は0以上である必要があります" |
| `maxPrice` | 任意、≥ 0 | "Maximum price must be 0 or more" | "最高価格は0以上である必要があります" |
| `rating` | 任意、1–5 | "Rating must be between 1 and 5" | "評価は1〜5の間である必要があります" |
| `sort` | 任意、price/rating/createdAt | "Invalid sort field" | "無効な並び順項目です" |
| `order` | 任意、asc/desc | "Invalid sort direction" | "無効な並び順です" |
| `page` | 任意、≥ 1 | "Page must be at least 1" | "ページは1以上である必要があります" |

### 8.2 バリデーション適用レイヤー

1. **フロントエンド（クライアント）**：`searchParamsSchema`（Zod）によるURLクエリパラメータのパースとcoercion。数値フィールドには`z.coerce.number()`を使用。
2. **バックエンド（サーバー）**：`GET /api/v1/products`でのNestJS ValidationPipe + class-validator DTO（whitelist + forbidNonWhitelisted）。
3. **データベース（DB）**：最終的な安全策としてのPrismaインデックスとCHECK制約（例：`chk_products_price`、`chk_products_stock`）。

## 9. エラーハンドリング仕様

### 9.1 エラーレスポンス構造

```json
{
  "statusCode": 400,
  "message": ["limit must not be greater than 100", "rating must not be greater than 5"],
  "error": "Bad Request",
  "timestamp": "2026-08-05T12:00:00.000Z",
  "path": "/api/v1/products"
}
```

### 9.2 エラー分類表 — 検索

| HTTPステータス | エラーコード | シナリオ | ユーザー向け動作 |
|---------------|-------------|----------|-----------------|
| `400` | `BAD_REQUEST` | バリデーション失敗（無効なパラメータ） | インラインバリデーションヒント + 上部バナー |
| `401` | `UNAUTHORIZED` | 保護されたアクションでトークンがない／無効 | ログインへリダイレクト |
| `403` | `FORBIDDEN` | アクセス拒否 | ログインへリダイレクト |
| `404` | `NOT_FOUND` | 商品詳細が見つからない（無効なslug） | 空状態／「商品が見つかりません」 |
| `429` | `TOO_MANY_REQUESTS` | パブリック検索のレート制限超過 | 「リクエストが多すぎます。お待ちください」+ リトライカウントダウン |
| `500` | `INTERNAL_SERVER_ERROR` | サーバーエラー | 「問題が発生しました」+ リトライボタン |

### 9.3 フロントエンドのエラー表示動作

- **フィールドレベルバリデーション**：無効なフィルタ入力（例：minPrice > maxPrice）の下に赤い枠線とインラインテキスト。
- **フォームレベルのサマリー**：結果エリア上部にすべてのエラーを一覧表示するアラートバナー。
- **ローディング状態**：フェッチ中のスケルトンシマーグリッド（shadcn `Skeleton`）。適用／検索ボタンにはスピナー。
- **空の結果**：メッセージ + イラスト付きの`EmptyState`コンポーネントと「フィルタリセット」ボタン。フィルタをクリアするかキーワードを広げるよう提案。
- **リトライ**：一時的な失敗に対するTanStack Queryの`error` + `refetch`。

### 9.4 監査／ロギング

| イベント | 記録されるデータ | 保持期間 |
|---------|-----------------|----------|
| `SEARCH_EXECUTED`（遅いクエリ > 500msの場合はwarnレベル） | userId（ログイン中の場合）、クエリパラメータ、結果件数、所要時間 | 30日 |

ルール：
- レスポンスボディ全体を決してログに記録しない（セキュリティ）。
- NestJSの`Logger`を`[SearchService]`コンテキストで使用。`console.log`は使用しない。

## 10. 権限とアクセス制御

### 10.1 認証要件

- 検索、カテゴリ閲覧、商品詳細のエンドポイントは**パブリック** — JWTは不要。
- レート制限は、不正使用から保護するためにパブリック検索エンドポイントに強制される。

### 10.2 パブリックと保護エンドポイント

| エンドポイント | アクセスレベル | 説明 |
|---------------|---------------|------|
| `GET /api/v1/products` | パブリック | 商品カタログの検索／フィルタ／並び替え／ページネーション |
| `GET /api/v1/categories` | パブリック | カテゴリツリー（ネストされたナビゲーション） |
| `GET /api/v1/products/:slug` | パブリック | 商品詳細（結果クリックから） |

### 10.3 ロールベースのアクセス

| ロール | 検索可能 | カテゴリ閲覧可能 | 商品詳細表示可能 |
|--------|:--------:|:---------------:|:----------------:|
| ビジター（ゲスト） | ✓ | ✓ | ✓ |
| `buyer` | ✓ | ✓ | ✓ |
| `merchant` | ✓ | ✓ | ✓ |

## 11. リアルタイム通知動作

### 11.1 現在の実装

検索・フィルタページは標準のREST API呼び出しで動作します。この機能にリアルタイムのWebSocket接続は必要ありません。商品の在庫状況と価格変更は次のクエリ時に反映されます（2分間のリストキャッシュTTLで緩和）。

### 11.2 クライアント側の状態更新

| イベント | トリガー | アクション |
|---------|---------|-----------|
| `search:paramChange` | URLクエリパラメータ変更 | 商品クエリを再フェッチ（TanStack Queryの無効化） |
| `search:debouncedInput` | キーワード入力（300msアイドル） | `q`パラメータを更新し再フェッチ |
| `search:filterApplied` | フィルタ適用／フィルタリセット | `page`を1にリセットし再フェッチ |
| `search:pageChange` | ページネーション制御のクリック | `page`を更新し、`keepPreviousData`付きで再フェッチ |

## 13. 非機能要件

### 13.1 パフォーマンス要件（パフォーマンス標準第10.3節）

| メトリクス | 目標 |
|-----------|------|
| 検索レスポンス時間（10Kレコード） | ≤ 3秒（NFR-002） |
| オートコンプリートレスポンス時間 | ≤ 200ms |
| フィルタ適用時間 | ≤ 500ms |
| デバウンス遅延（検索入力） | 300ms |
| APIレスポンス時間（p95） | ≤ 500ms（NFR-003） |
| データベースクエリ時間 | ≤ 50ms |
| キャッシュヒットレスポンス時間 | ≤ 200ms |

### 13.2 キャッシュ戦略（第5節／10.5）

| キャッシュ対象 | 戦略 | TTL | 無効化 |
|---------------|------|-----|--------|
| 商品リスト結果 | `cache:products:list:{hashOfQuery}`（文字列JSON） | 2分 | 商品の変更 → `DEL` |
| カテゴリツリー | `cache:categories`（文字列JSON） | 30分 | カテゴリの変更 → `DEL` |

ルール：
- キャッシュアサイドパターン：Redisを確認 → ミス → DBクエリ → Redisに投入。
- リストキャッシュキーはシリアライズされたクエリパラメータのハッシュで、フィルタごとのキャッシュをサポートする。
- 必ずTTLを設定する。機密データをキャッシュしないこと。

### 13.3 セキュリティ考慮事項

| 懸念事項 | 緩和策 |
|---------|--------|
| `q`でのSQLインジェクション | Prismaパラメータ化クエリ。SQLへの文字列補間なし |
| キーワード／URLパラメータでのXSS | Reactの自動エスケープ、`dangerouslySetInnerHTML`なし |
| 極端に長い`q`（> 255） | 400バリデーションエラー |
| `categoryId`の無効なCUID | 400バリデーションエラー |
| パブリック検索でのレート制限の不正使用 | しきい値超過で429 |
| データ漏洩 | 未承認ショップの商品はクエリレベルで除外（第12.2節） |

### 13.4 レスポンシブデザイン要件

| ブレークポイント | レイアウト |
|-----------------|-----------|
| デスクトップ（≥ 1024px） | フィルタサイドバー + 結果グリッド（4列） |
| タブレット（768px – 1023px） | フィルタサイドバー（狭め）+ グリッド（2–3列） |
| モバイル（< 768px） | フィルタドロワー（トリガーEL-28）+ 積み重ねグリッド（1–2列） |
