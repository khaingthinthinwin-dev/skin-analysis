## 2. 画面概要・目的

### 2.1 目的
管理者監査ログ画面は、Cosmetics Finderプラットフォーム内で実行されたすべての重要なシステムアクションについて、プラットフォーム管理者に完全な可視性を提供します。セキュリティ監視、コンプライアンス、運用責任のための中央監査トレイルとして機能します。この画面では、監査ログデータの表示、フィルタリング、検索、エクスポート、および90日以上経過したレコードの手動削除が可能です。

### 2.2 対象ユーザーと権限

| 属性 | 値 |
| :--- | :--- |
| **主要アクター** | プラットフォーム管理者（管理者ロール） |
| **認証要件** | JWT Bearer Token（`admin`ロール） |
| **データ範囲** | プラットフォーム全体の監査ログエントリ（追記のみ、90日以上経過したレコードは管理者による手動削除可能） |
| **アクセス制御** | 管理者のみルート — `JwtAuthGuard` + `RolesGuard`強制適用 |

### 2.3 主要機能・基本設計方針
1. **監査トレイル表示** — すべての監査ログエントリをソート可能、ページネーション付きテーブルで表示。
2. **高度なフィルタリング** — ユーザー、アクションタイプ、エンティティタイプ、日付範囲、IPアドレス、エンティティIDによるフィルタリング。
3. **ログ詳細検査** — 旧値/新値（JSON差分）、IP、ユーザーエージェントを含む完全な詳細を表示。
4. **検索** — アクション名、エンティティタイプ、ユーザー情報に対する全文検索。
5. **CSVエクスポート** — フィルタリングされた監査ログデータをCSV形式でエクスポート。
6. **リアルタイム監視** — 30秒ごとの自動更新機能。
7. **手動削除** — 90日以上経過したDB監査ログレコードの削除。
8. **国際化** — 英語、日本語、マレー語の完全なi18nサポート。
9. **レスポンシブデザイン** — デスクトップテーブルレイアウト、モバイルカードベースレイアウト。

## 5. 各項目における挙動・イベント仕様

### 5.1 ページ読み込み（`/admin/audit-logs`）
- **トリガー:** 管理者が`/admin/audit-logs`にナビゲート。
- **処理ロジック:**
  1. **認証チェック:** JWTトークンと`admin`ロールを検証。未認証の場合はログインにリダイレクト。
  2. **初期データ読み込み:** デフォルトパラメータ（`page=1`, `limit=50`, `sortBy=created_at`, `sortOrder=desc`）で`GET /api/v1/admin/audit-logs`を実行。
  3. **フィルターオプション読み込み:** アクションフィルターとエンティティタイプフィルタードロップダウンを入力するために`GET /api/v1/admin/audit-logs/filters`を実行。
  4. **レンダリング:** 結果を含む監査ログテーブルを表示。
- **例外処理:**
  - `403`（FORBIDDEN）: 認証ページにリダイレクト。
  - `500`（INTERNAL_SERVER_ERROR）: "監査ログの読み込みに失敗しました"エラーメッセージを表示。
  - ネットワークエラー: "ネットワークエラー。接続を確認してください"を表示。

### 5.2 自動更新トグル（`tglAutoRefresh` onChange）
- **トリガー:** 管理者が自動更新スイッチをトグル。
- **処理ロジック:**
  1. **有効な場合:** ポーリング間隔（30秒）を開始。各間隔で、現在のフィルターを使用して監査ログリストを再取得。
  2. **無効な場合:** ポーリングを停止。現在のリストデータを保持。
  3. **一時停止動作:** ページが非表示の場合、またはリフレッシュリクエストが実行中の場合はポーリングを一時停止。
- **例外処理:**
  - リフレッシュエラー: 既存のデータを保持し、ブロックしないエラー通知を表示。次の間隔で自動リトライ。

### 5.3 CSVエクスポート（`btnExportCsv` onClick）
- **トリガー:** 管理者が「CSVエクスポート」ボタンをクリック。
- **処理ロジック:**
  1. **クライアント側事前チェック:** エクスポートする監査ログエントリが存在することを確認。
  2. **バックエンドディスパッチ:** 現在のフィルターパラメータ + `{ format: 'csv' }`で`POST /api/v1/admin/audit-logs/export`を実行。
  3. **バックエンド実行:** 入力を検証（日付範囲最大365日、行数最大10,000）。CSVファイルを生成。ファイルを保存（自動TTLなし）。ダウンロードURLを返却。
  4. **実行後UI:** ファイルダウンロードをトリガー。成功トーストを表示。
- **例外処理:**
  - `400`（BAD_REQUEST）: "エクスポートが最大行制限（10,000）を超えています。フィルターを絞り込んでください。"を表示。
  - `500`（INTERNAL_SERVER_ERROR）: "レポート生成に失敗しました。再試行してください。"を表示。
  - ネットワークエラー: "ネットワークエラー。接続を確認してください"を表示。

### 5.4 監査ログ削除ボタン（`btnDeleteLogs` onClick）
- **トリガー:** 管理者が「監査ログ削除」ボタンをクリック。
- **処理ロジック:**
  1. **認可チェック:** 管理者ロールを検証。非管理者ユーザーにはボタンを非表示。
  2. **ダイアログを開く:** 手動削除確認ダイアログを表示（第4.6項）。
- **例外処理:**
  - なし（権限がない場合はボタンを非表示）。

### 5.5 保持期間入力（`txtRetentionDays` onChange）
- **トリガー:** 管理者が保持期間の値を変更。
- **処理ロジック:**
  1. **バリデーション:** 90以上でなければならない。
  2. **サマリーの更新:** 新しい値で削除範囲サマリーテキストを更新。
  3. **確認ボタンの有効/無効:** バリデーションに失敗した場合は確認ボタンを無効に。
- **例外処理:**
  - 無効な入力: インラインエラーメッセージを表示。確認ボタンを無効に。

### 5.6 削除確認（`btnConfirmDelete` onClick）
- **トリガー:** 管理者が「削除を確認」ボタンをクリック。
- **処理ロジック:**
  1. **クライアント側事前チェック:** 保持期間 >= 90を検証。
  2. **バックエンドディスパッチ:** `{ olderThanDays: <入力値> }`で`DELETE /api/v1/admin/audit-logs/files`を実行。
  3. **バックエンド実行:** JWTトークンと管理者ロールを検証。`created_at`がしきい値より古いDBレコードを選択。制御されたバッチで削除。削除されたレコード数を返却。
  4. **実行後UI:** ダイアログを閉じる。成功トーストを表示。リストをリフレッシュ（または自動更新がオフの場合は再取得）。
- **例外処理:**
  - `400`（BAD_REQUEST）: "最小保持期間は90日です"または"削除対象のレコードがありません"を表示。
  - `403`（FORBIDDEN）: "アクセスが拒否されました"を表示。
  - `500`（INTERNAL_SERVER_ERROR）: "削除に失敗しました。再試行してください。"を表示。ダイアログはリトライ用に開いたまま。
  - ローディング状態: 確認ボタンにスピナーを表示。リクエスト中はすべての入力を無効に。

### 5.7 詳細表示（`btnViewDetail` onClick）
- **トリガー:** 管理者がログ行の「詳細表示」ボタンをクリック。
- **処理ロジック:**
  1. **バックエンドディスパッチ:** `GET /api/v1/admin/audit-logs/:id`を実行。
  2. **バックエンド実行:** IDで監査ログエントリを検索。実行者詳細のためにusersテーブルと結合。完全な監査ログDTOを返却。
  3. **実行後UI:** 監査ログ詳細モーダルを表示（第4.4項）。
- **例外処理:**
  - `404`（NOT_FOUND）: "監査ログエントリが見つかりません"エラーを表示。
  - `500`（INTERNAL_SERVER_ERROR）: "監査ログ詳細の読み込みに失敗しました"を表示。

### 5.8 ユーザー履歴表示（`btnViewUserHistory` onClick）
- **トリガー:** 管理者が詳細モーダルの「ユーザー履歴を表示」ボタンをクリック。
- **処理ロジック:**
  1. **モーダルを閉じる:** 詳細モーダルを閉じる。
  2. **ナビゲート:** `/admin/audit-logs?userId={entity.user_id}`にナビゲート。
  3. **再取得:** 選択されたユーザーのエントリのみを表示するようにフィルタリングされた監査ログリスト。
- **例外処理:** 該当なし。

### 5.9 エンティティ履歴表示（`btnViewEntityHistory` onClick）
- **トリガー:** 管理者が詳細モーダルの「エンティティ履歴を表示」ボタンをクリック。
- **処理ロジック:**
  1. **モーダルを閉じる:** 詳細モーダルを閉じる。
  2. **ナビゲート:** `/admin/audit-logs?entityType={entity.entity_type}&entityId={entity.entity_id}`にナビゲート。
  3. **再取得:** 選択されたエンティティのエントリのみを表示するようにフィルタリングされた監査ログリスト。
- **例外処理:** 該当なし。

### 5.10 フィルタークリア（`btnClearFilters` onClick）
- **トリガー:** 管理者が「フィルターをクリア」リンクをクリック。
- **処理ロジック:**
  1. **状態リセット:** すべてのフィルター値をデフォルトにリセット。
  2. **再取得:** デフォルトパラメータで`GET /api/v1/admin/audit-logs`を実行。
  3. **UI更新:** フィルタークリアリンクとアクティブフィルターバッジを非表示。
- **例外処理:** 該当なし。

### 5.11 ページネーション（`btnPrevPage` / `btnNextPage` / `btnPageNumbers` / `selPageSize` onClick/onChange）
- **トリガー:** 管理者がページナビゲーションをクリック、またはページサイズを変更。
- **処理ロジック:**
  1. **状態更新:** ページ番号または制限値を更新。
  2. **再取得:** 更新されたパラメータで`GET /api/v1/admin/audit-logs`を実行。
  3. **UI更新:** テーブル、ページネーションコントロール、ページ情報テキストを更新。
- **例外処理:**
  - `400`（BAD_REQUEST）: "無効なページネーションパラメータ"を表示。

### 5.12 エンティティIDリンク（`colEntityId` onClick）
- **トリガー:** 管理者がテーブルのエンティティIDリンクをクリック。
- **処理ロジック:**
  1. **ナビゲート:** entity_typeに基づいて、適切な詳細ページにナビゲート:
     - Merchant: `/admin/merchants/:entityId`
     - Product: `/admin/products/:entityId`
     - Order: `/admin/orders/:entityId`
     - Advertisement: `/admin/advertisements/:entityId`
     - User: `/admin/users/:entityId`
  2. entity_idがnullの場合は"—"（ダッシュ）を表示し、リンクなし。
- **例外処理:** 該当なし。

1. **フロント側（クライアント）:** React Hook Form + Zodスキーマバリデーションによるリアルタイムフィードバック。

## 7. レスポンシブレイアウト動作

### 7.1 デスクトップ（≥1024px）
- すべてのカラムが表示されるフルテーブルレイアウト
- 水平フィルターバー
- 詳細表示用サイドパネルモーダル（幅400px）
- 削除確認用センタードダイアログ（幅480px）

- 水平スクロール付きレスポンシブテーブル
- ラップされたフィルターグリッド
- フル幅モーダル
- フル幅ダイアログ

### 7.3 モバイル（<768px）
- カードベーステーブルレイアウト（各行がカードに変換）
- 積み重ねフィルター（垂直レイアウト）
- フルスクリーンモーダル
- フルスクリーンダイアログ

## 8. アクセシビリティ要件

| 要件 | 実装 |
| :--- | :--- |
| キーボードナビゲーション | すべてのインタラクティブ要素がTabキーでフォーカス可能。Enter/Spaceでボタンをアクティブ化。Escapeでモーダルを閉じる。 |
| スクリーンリーダーサポート | すべてのフォームフィールドに`htmlFor`/`id`による関連ラベルあり。アイコンボタンにARIAラベル。動的コンテンツ更新にライブリージョン。 |
| カラーコントラスト | すべてのテキストとインタラクティブ要素でWCAG 2.1 AA準拠。 |
| フォーカス管理 | モーダル内でフォーカスをトラップ。モーダルが閉じたときにトリガー要素にフォーカスを戻す。 |
| エラー通知 | バリデーションエラーをスクリーンリーダー用に`aria-live="polite"`で通知。 |
